## 已确认基线

### OQ-001：持仓是否区分券商？

**决定（2026-08-20 修订）：** 首页股票持仓不区分券商；v4 内部但以固定 IBKR/moomoo 记录股票来源。

- 不建立自由券商账户、标签或首页股票筛选/拆分；
- 券商只在校准、买入、卖出和内部来源成本校验中使用；
- 用户统一录入数据；
- 同一标的统一计算，只展示合并后的持仓；
- 首页重点是直观显示组合总仓位。

**决定者：** 产品所有者
**决定日期：** 2026-07-30
**状态：** 已关闭。

该决定取代此前“首页先按券商拆分再合并”的产品假设。ADR-044 后，券商维度只在底层来源持仓中恢复，用于超卖、剩余成本和交易原子性；ADR-048 后用户可见现金仍是一个组合池。产品不连接券商账号或 API。

### OQ-005：是否需要知道两家券商的名称？

**决定（2026-08-20 修订）：** 用户不需要创建或管理券商账户；启用 v4 后，只在校准和交易时看到固定 IBKR/moomoo 股票来源。

IBKR 还用于利息口径；IBKR/moomoo 都可用于股票来源校验。它们不形成自由账号管理、首页股票拆分或两个用户可见现金池。

**决定者：** 产品所有者
**决定日期：** 2026-07-30
**状态：** 已关闭，不适用。

### OQ-006：行情是否包含盘前、盘后和隔夜？

**决定：** 包含。App 全天展示可用估值，并跟随美股实际市场时段。

- 美东盘前、常规盘和盘后使用 Alpaca `delayed_sip` 最新成交；
- 美东 20:00–04:00 的 24/5 隔夜时段使用 Alpaca `overnight` 派生行情；
- 两类成交价都按约 15 分钟延迟表达，隔夜成交同时标为指示性价格；
- 股票没有新的隔夜成交、周末、节假日或市场休市时，继续显示最近有效价并保留原行情时间，不显示 `0`；
- 数据层保留盘前、常规盘、盘后、隔夜或休市、实际 feed、价格类型与事件时间；首页只在页面级披露一次约 15 分钟延迟，不逐行显示市场时段、时间、老化、上一有效价或隔夜提醒；
- App 在前台每分钟刷新，重新回到前台时补刷；关闭 App 或 iOS 暂停后台页面时不承诺后台持续运行。

这项决定是估值与数据保留规则，不扩大为交易、下单或可成交价格承诺。不是所有股票都会在每个扩展时段持续成交；没有新成交时必须在数据层保留上一有效价及其真实状态和时间。首页可见状态由 ADR-020 修订：从未取得有效价格时明确缺价，请求故障可使用紧凑的页面级提示，不逐行展示旧价或老化标签。

**决定者：** 产品所有者
**决定日期：** 2026-07-30
**状态：** 已关闭。行情选择绑定 ADR-016；首页可见表达由 ADR-019、ADR-020 修订。

### OQ-002：以后怎样维护持仓，部分卖出怎样计算？

**决定（2026-08-20 修订）：** 旧 current 快照批次继续保留；用户确认校准后，v4 双券商账本以固定 IBKR/moomoo 的手工 BUY/SELL 驱动 current，首页仍按标的合并。长期历史事件与 NAV 导入仍停用。

- 一个批次描述保存时一个标的的全部当前输入；
- 同一标的可以录入多组数量与成本；
- 成本录入同时支持平均成本和剩余总成本两种模式；
- 未启用 v4 时，普通录入、修改和加仓继续作用于旧快照；
- 首次启用必须按两家券商当前数量、剩余成本和已结算/待结算现金校准，不从旧聚合值猜来源，旧 v3 current 不改写；
- v4 启用后，首页股票菜单提供买入、卖出、校准和复制；买卖只选择股票来源券商，并与统一组合现金原子联动；
- 部分卖出按所选券商卖出前移动平均成本等比例扣减剩余成本，全卖只移除该券商子持仓；另一券商不变；
- v4 事件用于 current 审计、JSON v3 和继续交易，不生成长期收益；
- 保存必须原子完成；存储层可以保留上一版本作为故障防护，但首页不提供历史恢复入口；
- 2026-08-11 确认过的历史中心、`BUY / SELL / DEPOSIT / WITHDRAWAL` 和 IBKR/moomoo 导入已于 2026-08-12 退出运行路径；既有本机历史数据不删除；
- 当前产品不计算或展示税务口径已实现盈亏；不支持 FIFO、指定批次或税务成本。

如果以后要求长期历史收益或税务盈亏，仍需单独确认 v4 事件与 NAV/外部现金流的组合、批次选择、已实现盈亏和迁移规则。

**决定者：** 产品所有者
**决定日期：** 2026-07-30；2026-08-12、2026-08-20、2026-08-22 修订
**状态：** 已关闭。绑定决定见 ADR-011、ADR-015、ADR-017、ADR-037、ADR-044 与 ADR-048。

### OQ-018：长期组合收益采用什么真值与现金流口径？

**历史决定：** 2026-08-11 曾决定 `1W / 1M / 3M / 1Y / ALL` 使用独立本机历史库中的真实 NAV 与外部现金流。产品所有者在 2026-08-12 判定长期范围不可实现并将其全部撤回；首页现在只保留真实 `1D` 今日走势。

- 入金为正外部现金流，出金为负外部现金流；两者的直接资产影响从收益中剔除；
- 买卖、内部转账、换汇、股息、利息、税费、佣金和融资利息留在组合表现中；
- IBKR/moomoo 文件只在浏览器本机解析，原始文件、姓名和完整账户号不持久化或上传；
- 历史期权通过券商 NAV 进入整体收益，不当作股票数量；
- 只有交易确认而没有 NAV 时可记录交易，但不能生成长期收益；
- 缺 NAV、未知现金分类、来源覆盖不一致或分母无效时结果为部分/不可用，真实缺口断线，不补零或插值；
- `1D` 继续使用 ADR-034 的当前持仓日内估算，与长期账户收益口径分别标注。

**决定者：** 产品所有者

**决定日期：** 2026-08-11；2026-08-12 撤回

**状态：** 已关闭并被取代。绑定决定见 ADR-035 与 ADR-037。

### OQ-004：数据保存在本地、云端还是两者都有？

**决定（2026-08-20 修订）：** OpenAI Sites Production 使用登录账号 D1 作为股票、现金和双券商 current 真值；同一 ChatGPT 账号跨设备读取同一组合。

- 访问必须通过 Sites ChatGPT 登录；资产按 `oai-authenticated-user-id` 隔离，不持久化邮箱；
- D1 `state_version` compare-and-swap 与领域 revision 同时阻止多设备静默覆盖；
- Sites IndexedDB 只保留表单草稿、上一有效行情、USD/CNY 缓存和提示时间，不再承载活动资产；
- 旧 Vercel origin 的 IndexedDB 保持原样。由于 origin 隔离，Sites 不自动读取或上传旧数据；迁移只能先导出 JSON v2/v3，再在空账号中预览、二次确认和恢复；
- 每个标的新版本以及 v4 股票/现金/事件仍必须整体成功或零变化；
- JSON 继续作为用户可带走的独立副本，不等同于自动云备份快照。

跨账号共享、自动版本化云备份、账号删除/数据导出 SLA 与完整离线仍需另行确认。

**决定者：** 产品所有者
**决定日期：** 2026-07-30；2026-08-20 修订
**状态：** 已关闭。绑定决定见 ADR-045；ADR-012 只描述旧 Vercel 来源。

### OQ-014：是否需要把当前手机持仓导出并从空组合安全恢复？

**决定（2026-08-20 修订）：** 需要。用户可手动导出当前账号的 current-only JSON v2/v3，并允许把规范化 current 安全恢复到 positions/cash/broker 全空的登录账号；导出、校验、取消、冲突或失败不得弄丢现有数据。

- 旧 positions/cash current 使用 JSON v2；v4 book 与其 current 维护事件使用 JSON v3；
- `snapshots` 只包含每个标的当前活动 `PositionSnapshot`，保留 revision、保存时间、标的、可选名称和全部原始输入；
- `cash` 只包含当前 IBKR USD 现金 snapshot，保留 revision、保存时间、余额、Pro/Lite、NAV 与 NAV 来源；没有现金时为 `null`；
- 数量和成本继续使用十进制字符串；
- 不包含股票或现金上一版本、持仓或录入页草稿、行情缓存、legacy 券商备份、outbox 或同步游标；
- 导出只读调用账号 repository，不改变 D1 state revision、不提升 IndexedDB schema，不修改或清空任何账号或本地数据；
- 文件优先通过 Web Share 交付，不支持时回退为本地 Blob 下载；
- 应用不把文件上传 Vercel。用户在系统分享面板中选择“存储到文件”、iCloud Drive 或其他目标属于用户主动保存，不代表产品已经提供云备份；
- `[用户确认 2026-08-09；2026-08-20 修订]` 恢复只接受严格 JSON v2/v3，先在当前设备校验并预览，再二次确认；未知格式/版本、无效字段/十进制/时间/源 revision、范围外或歧义标的、无效现金/book 和空备份都拒绝写入；
- `[用户确认 2026-08-09；2026-08-20 修订]` 目标 positions、cash 与 broker 必须同时为空，不合并、不覆盖。Sites 服务端在同一 D1 CAS 中重验文档、复查空目标并写入规范化 current；任何校验、竞争或写入失败都零变化；
- `[用户确认 2026-08-09；2026-08-20 修订]` 源 current revision 只校验，不继承。新账号 current 固定 `revision=1`、`nextRevision=2`、`previous=null`；原始文件不持久化，录入草稿、行情/汇率缓存、legacy、outbox 和同步游标不进入 D1。

该决定解决“把当前账号资产导出为用户可持有副本，并在完全空账号中自助恢复 current”的风险。同账号跨设备读取由 OQ-004/ADR-045 的 D1 current 提供；自动版本化云备份、合并或覆盖已有账号仍需新决定。

`[用户确认 2026-08-20]` ADR-044 的 JSON v3 只承载 v4 current book 与 current 维护事件；恢复后账号 revision 重置为 1、`previous=null`，不改变 v2 contract，也不提供合并或覆盖。

**决定者：** 产品所有者

**决定日期：** 2026-07-30；恢复边界于 2026-08-09 确认

**状态：** 已关闭。绑定决定见 ADR-018、ADR-023 与 ADR-031。

### OQ-015：怎样把持仓资料交给用户自行选择的 AI？

**决定（2026-08-12 修订）：** 保留同一套本机结构化文本与范围，并提供“仅复制持仓资料”和“复制并打开 ChatGPT”两个明确目标。

- 首页支持前 5、前 10、全部资产和单只股票范围；前 5/前 10 按股票未舍入市值降序，缺价置后；全部资产在存在现金时包含现金；
- 单只文本包含完整组合摘要、该股聚合数量与成本、估值、盈亏、占已计价总资产比例和股票市值排名，权重分母包含现金本金，但不展开其他股票；
- `[用户确认 2026-08-03]` 文本面向 AI 建议压缩为组合摘要与紧凑持仓表，只保留会改变判断的资产、定价完整性、成本、盈亏、现金、仓位、范围覆盖和持仓核心数据；
- 逐股 provider、feed、市场时段、行情状态、价格类型、事件时间和获取时间不重复进入剪贴板，改为组合级延迟/非实时说明、价格时间范围，以及上一有效价和隔夜指示价例外标记；
- 文本只陈述事实，不附带 AI 提问或买卖建议；投资目标、风险承受能力、期限、税务和流动性需求由用户在对话中另行说明；
- 用户先选目标再选前 5、前 10、全部或单只范围；普通复制只写入系统剪贴板并留在 PWA，ChatGPT 路径先调用剪贴板，再通过 `https://chatgpt.com/?prompt=<编码文本>` 打开待发送 Prompt；iOS App 未接管时允许回落网页；
- ChatGPT 中的 Prompt 必须停在待发送状态，由用户核对并手动发送。PWA 不调用 OpenAI API、不持有 ChatGPT token、不自动发送，也不接收或展示回答；
- App 不把复制文本上传本产品或 Vercel 后端，不增加账号、API key 或资产写操作；普通复制没有外部导航，只有用户明确选择 ChatGPT 时，HTTPS 导航才把 Prompt 作为 URL 参数交给外部数据边界；
- 系统剪贴板不可用、被拒绝，或 ChatGPT 未完整预填时，显示或保留相同内容的只读文本供手工复制/粘贴；不得误报已发送；
- 复制成功只使用目标专属的短暂 Toast：普通复制提示可粘贴到其他应用，ChatGPT 路径提示已经打开 ChatGPT；不在总览下方保留页面级提示；
- App 接管、网页回落、未登录状态、中文换行、长文本完整性和 URL 隐私暴露必须在真实 iPhone Safari 与主屏幕 PWA 中验证；未验证前不承诺稳定路由或长度上限。

ChatGPT 路径的自动发送、固定会话/机器人、把外部 ChatGPT 回答带回 PWA、截图或图片分享仍需重新确认。服务端 DeepSeek 组合咨询已于 2026-08-15 作为独立的弹层内多轮能力确认，见 OQ-019；它不改变本节两个复制目标的文本与交付边界。

**决定者：** 产品所有者

**决定日期：** 2026-08-01；ChatGPT 交付于 2026-08-09 修订；双目标于 2026-08-12 修订

**状态：** 已关闭。绑定决定见 ADR-021、ADR-026、ADR-033 与 ADR-038。

### OQ-016：是否把 IBKR USD 现金计入组合，并怎样估算利息？

**决定：** 需要。旧 v3 最多保存一条手工录入的 IBKR USD 现金；v4 按 ADR-048 只向用户展示一个组合现金池，并把本金计入总资产。

**2026-08-20、2026-08-22 修订：** 上述单条记录继续作为旧 v3 current。启用 ADR-044 后，v4 底层继续保存 IBKR 与 moomoo 的已结算/待结算 USD 以兼容现有 current、结算和利息口径；产品只把它们的合计显示为一个组合现金池。只有正 IBKR 已结算 USD 参与本节利息估算，其他内部分量、待结算和负现金排除。

- 首页连续列表提供 IBKR 现金入口和现金行；用户填写 USD 余额、IBKR Pro/Lite 和可选的 IBKR 账户 NAV；
- IBKR 是利息口径的 provider，IBKR/moomoo 还是 v4 股票来源；产品不连接任一券商账户或读取实际余额，并且不把底层分量展示成两个现金池；
- `[外部事实 2026-08-02]` Interactive Brokers 官方现金利率页对直接客户公布 USD 正结算现金档位：Pro `3.13%`、Lite `2.13%`；首 USD 10,000 不计息，NAV 达到 USD 100,000 使用完整档位，低于门槛按 NAV 比例调整；利率可变；
- 未填写 NAV 时暂按现金余额作为 NAV，并在表单、首页和复制资料中披露；不得用本 App 的股票总资产代替 IBKR NAV；
- 预估年利息等于 `max(现金余额 - 10000, 0) × 档位利率 × min(NAV / 100000, 1)`；月均估算为年估算除以 12；全部使用未舍入十进制真值；
- 现金本金计入总资产与 CNY 派生显示；未入账利息只作为估算，不计入现金余额、总资产、浮动盈亏或收益率分子；
- 旧 Vercel origin 的现金保留在独立 IndexedDB store，schema v2→v3 兼容升级不重写已有股票、草稿或行情缓存；Sites 中的旧 cash current 或 v4 book 物理写入 D1，IndexedDB 不再是活动现金真值；
- JSON v2/v3 和“全部资产”复制包含对应 current 的统一现金口径；App 仍无券商登录、自动券商同步或实际入账核对，Vercel provider 不持久化账号 current；
- 页面链接官方利率页并显示核验日，不声称利率实时、固定或保证收益。

未来若需要其他币种、其他券商、多 IBKR 账户、自动读取余额、实际计息流水或动态同步利率，必须重新确认数据模型、鉴权、安全、费用和迁移。

**决定者：** 产品所有者

**决定日期：** 2026-08-02

**状态：** 已关闭。绑定决定见 ADR-023 与 ADR-044。

### OQ-007：P0 支持哪些标的？

**决定：** P0 支持 Alpaca 能正常解析的 USD 计价美国上市股票与 ETF。

- 不支持 OTC、期权、加密货币和非美国市场；
- 美国存托凭证（ADR）若能被 Alpaca 作为受支持的美国上市股票正常解析，则可以录入；
- 标的身份仍包含上市市场、规范代码与币种，不能只靠显示名称或裸代码合并；
- 用户录入时只填写股票代码；Alpaca 自动返回上市市场，币种固定为 USD，页面不要求用户选择市场或币种；

### OQ-012：CNY 汇率使用什么数据源和新鲜度？

**决定：** 优先使用 Alpaca 最新外汇汇率接口的 `USDCNY` 中间价 `mp`；Alpaca 未配置或不可用时，使用欧洲央行每日参考价计算 USD/CNY 交叉汇率。

### OQ-008：首页是否需要整个股票仓的“今日盈亏”？

**决定（2026-08-08 修订展示层）：** 需要，但不设置独立入口或持仓表模式切换。总资产 2 × 2 核心指标显示“今日盈亏”，主值显示整个股票仓的今日盈亏估算金额，副值显示组合今日涨跌幅；其余三项为累计盈亏、股票成本和现金本金。两者随当前可用行情刷新。持仓表第四列固定显示累计盈亏/收益率，第五列显示每只股票的今日涨幅与小字今日盈亏金额，行内不重复“估算”。

- 今日盈亏使用当前股票数量相对最近常规收盘价估算；夜盘使用 `overnight` 指示价，并从同批 `delayed_sip` Snapshot 取得最近常规收盘参考；
- IBKR USD 现金本金、NAV 和未入账利息都不计入今日盈亏金额或涨跌幅分母；
- 组合值只有在全部股票都具备有效估值价和前收盘价时显示，缺失值不按 `0` 处理；
- 逐股第五列主值显示 `estimatedDailyChangeRate`，下方小字显示同一结果的今日盈亏金额且不重复“估算”；缺少估值价或前收时显示 `— / 暂无`，IBKR 现金显示 `— / 不参与`；
- 持仓数量在当日发生变化时，该指标不等于券商按逐笔交易计算的当日盈亏；
- USD 是计算真值，人民币模式从未舍入 USD 今日盈亏金额派生显示；
- 页面继续披露约 15 分钟延迟和“估算”，不得称为实时行情或逐笔交易盈亏。

规范公式为：

```text
estimatedDailyPriceEffect =
  currentQuantity × (valuationPrice - previousRegularClose)
```

**决定者：** 产品所有者

**决定日期：** 2026-08-03（同日增加逐股第五列；修订 2026-08-02 初版决定）

**状态：** 已关闭。界面使用“今日盈亏”，金额为主值、涨跌幅为副值，并保留“估算”边界；持仓第五列直接显示逐股今日涨幅与小字金额。持仓名称列固定、其余列整表横向滑动。绑定决定见 ADR-024、ADR-025、ADR-027、ADR-028 与 ADR-029。

### OQ-022：买卖现金按标的或券商拆分，还是统一进组合现金？

**决定：** 统一进组合现金，不设置 BOXX、SGOV 或其他 symbol 特例。

- 卖出任意受支持股票的现金变化都是 `quantity × unitPrice - fee`，并加入组合现金；
- 买入任意受支持股票的现金变化都是 `-(quantity × unitPrice + fee)`，并从组合现金扣减；
- 券商只用于确认从哪一边增加/扣减股票数量与剩余成本，不要求用户选择现金账户；
- 首页和交易预览只显示 IBKR/moomoo 内部现金分量之和；底层分量继续保留以兼容既有 D1 current、JSON v3、结算状态与 IBKR 利息口径，不迁移或覆盖现有数据；
- 股票、组合现金与事件继续原子同写，失败零变化。

**决定者：** 产品所有者

**决定日期：** 2026-08-22

**状态：** 已关闭。绑定决定见 ADR-048。
