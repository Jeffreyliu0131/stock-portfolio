# 验收标准：iPhone 美股统一持仓 PWA

## 1. 验收边界

本文件验收 2026-07-30 至 2026-08-23 已确认的首版闭环：

- 无需创建、重命名或管理自由券商账号；v4 交易只在固定 IBKR/moomoo 中选择股票来源；
- 从底部唯一“录入资产”入口进入当前模式操作：旧 current 可录入股票或 IBKR USD 现金，v4 可校准或买入股票；
- 按标的保存完整当前持仓批次；同一标的可有多组输入；
- 成本录入支持平均成本或剩余总成本；
- 普通录入已有标的时原子叠加新输入并重算；
- 首页点按或长按持仓打开当前模式操作：旧 current 为修改/加仓/删除，v4 为买入/卖出/校准；两种模式都保留只读复制和横滑误触抑制；
- 相同标的合并；
- Alpaca 可解析的 USD 美国上市股票与 ETF；
- ChatGPT 登录、Sites D1 账号 current 与同账号跨设备读取；IndexedDB 只保留设备草稿和缓存；
- 当前活动资产的 JSON v2/v3 导出，以及只面向账号 positions/cash/broker 全空目标的严格预览、二次确认和 D1 CAS current-only 恢复；不合并、不覆盖，失败零变化，成功时恢复为 `revision=1`、`nextRevision=2`、`previous=null` 的账号 current；原始文件不持久化，Vercel provider 不接收文件；
- 前 5、前 10、全部或单只聚合持仓资料的双目标交付；“仅复制持仓资料”写入剪贴板并留在 PWA，“复制并打开 ChatGPT”复制同一文本后通过 `https://chatgpt.com/?prompt=` 打开待发送 Prompt。两者复用相同组合摘要与紧凑表，不自动发送或调用 OpenAI API，失败时可手工复制/粘贴；
- 首页 USD / 人民币显示模式；人民币从未舍入 USD 真值和一笔有效 USD/CNY 汇率派生，优先使用 Alpaca 中间价并以欧洲央行日参考交叉汇率降级，失败时诚实继续 USD；
- 旧 current 的 IBKR USD 现金录入/修改/删除与公开利率/NAV 估算；v4 只显示一条组合现金，底层分量只保留兼容、结算和 IBKR 利息口径。Sites 活动现金/book 写 D1，旧 v2→v3 IndexedDB 升级只作 legacy 保护验收；
- 总资产下方固定 2 × 2 核心指标：累计盈亏、今日盈亏、股票成本和现金本金；今日盈亏主值为全股票仓估算金额，副值为组合涨跌幅。夜盘也随行情刷新，持仓表第四列固定显示累计盈亏/收益率，第五列显示逐股今日涨幅与小字今日盈亏金额，现金完全排除且缺价不归零；
- 组合结构、Top 1/3/5 集中度、现金占比和今日绝对贡献；结构缺价标为部分口径，净额要求全量，贡献缺失不补 `0`；
- 首页提供“组合分析”和“AI 对话”两个独立入口与弹层；点按组合分析直接触发 DeepSeek V4 Flash 六维体检，打开 AI 对话零请求、发送问题才建立 current-only USD 固定快照并携带最近有限轮对话。运行界面不展示前置披露、同意页、示例、建议问题或重新体检；逐只 AI 行业/资产角色推断、本机 Decimal 暴露、数字重绘、高级风险数据缺口、非法输出整份拒绝和故障不影响确定性详情继续有效；
- 首页不显示账户身份、账户导航或资产类别假标签；刷新行情、导出数据副本和复制持仓资料统一放入“更多操作”；
- Production 不再内置或自动恢复固定个人股票/现金；全新 Sites 账号保持空组合，旧 Vercel origin 的 current、历史数据和旧标记不被读取、上传或改写；
- 来源持仓校准、IBKR/moomoo 子持仓、统一组合现金、原子 BUY/SELL、待结算/负现金、统一投影和严格 JSON v3；旧 v3 current 在启用前后不被迁移或改写；
- Robinhood-inspired 连续纯黑英雄区，承载总资产、今日收益、唯一“今日走势”与 2 × 2 指标；该线使用 SIP 15 分钟当前持仓估算，不显示长期周期或历史入口，不画假线；
- 首页第一屏直观看到总仓位；
- 跟随盘前、常规盘、盘后和 24/5 隔夜的 Alpaca 延迟行情，页面级单次延迟披露及诚实错误状态；
- 十进制安全；
- iPhone PWA 主路径。

### AC-HISTORY-01：长期周期与历史入口已撤回

**Given** 首页已载入

**When** 用户查看总资产英雄区、更多操作和空组合状态

**Then** 页面只保留“今日走势”，不在趋势图下重复当前股数估算与现金排除小字；没有 `1W / 1M / 3M / 1Y / ALL` 按钮、长期收益占位或历史导入链接，2 × 2 今日指标保持今日口径。

### AC-HISTORY-02：历史路由退出运行路径

**Given** 用户直接访问 `/history`，包括携带旧 `#history-text=` fragment

**When** 路由处理请求

**Then** 立即返回首页，不渲染粘贴、文件选择、预览确认或事件录入界面，也不读取或写入历史库。

### AC-HISTORY-03：既有历史数据保留但不再累积

**Given** 设备可能已有独立历史 IndexedDB 记录

**When** 首页加载、刷新行情或卸载本次界面能力

**Then** 控制器不打开历史 repository、不查询长期系列、不写入每日 NAV；已有历史数据不被删除或修改，current v3 继续独立运行。

### AC-STARTUP-01：Production 不自动写入固定资产

**Given** 一个全新的 Sites 登录账号，positions、cash 与 broker current 同时为空

**When** 首页首次加载并重复刷新

**Then** 页面始终显示真实空组合；不调用 current-only 恢复，不向 D1 创建股票、现金或 v4 book，不写入个人启动完成标记，不打开或写入历史库。

**And** 旧 Vercel origin 在升级前已有的 current、previous、草稿、缓存、历史数据或旧完成标记都不被 Sites 删除、迁移或改写。

### AC-AUTH-01：未登录不能进入资产页面

**Given** 访客没有有效 ChatGPT 登录身份

**When** 打开 Sites Production 的首页、录入、校准、交易或数据安全页面

**Then** Sites 分发层要求登录；应用页面不会匿名渲染资产，`/api/portfolio` 直接请求返回 401。

### AC-CLOUD-01：同一账号跨设备读取同一 current

**Given** 设备 A 登录账号 U，并成功保存一笔 current 变更

**When** 设备 B 使用同一账号 U 打开或刷新 Sites

**Then** B 从 D1 读取相同 revision、股票、现金和 v4 book；展示缓存和本机草稿不改变账号真值。

### AC-CLOUD-02：账号之间严格隔离

**Given** 账号 U 与账号 V 访问同一 Site

**When** U 写入组合，V 随后读取

**Then** D1 只用各自 `oai-authenticated-user-id` 选取行；V 看不到 U 的 current，邮箱不作为数据库键或持久字段。

### AC-CLOUD-03：多设备冲突不静默覆盖

**Given** 两个页面都读到同一 D1 `state_version` 和领域 revision

**When** 两边几乎同时写入不同变更

**Then** 最多一个 compare-and-swap 成功；另一个收到 409/冲突提示且零变化，必须刷新后再决定，不使用 last-write-wins。

### AC-MIGRATION-01：旧 origin 只能显式 JSON 迁移

**Given** 旧 Vercel origin 有 IndexedDB current，而 Sites 账号为空

**When** 用户第一次进入 Sites

**Then** Sites 不读取或自动上传旧 origin 数据。用户必须先从旧版导出 v2/v3，在 Sites 严格预览并二次确认；确认后只把规范化 current 写入空账号，原始文件、草稿、缓存和历史不持久化。

### AC-SITES-01：Production 保持 owner-only

**Given** 一个通过完整构建和 migration 检查的 Sites saved version

**When** 发布 Production

**Then** private deployment 验证当前调用者是唯一显式 viewer、没有群组或 public access；返回 Sites Production URL，D1 `DB` 生效，Sites 不配置 Alpaca 或 DeepSeek secret。

### AC-PROXY-01：Sites 只请求固定 Vercel provider

**Given** 浏览器页面的 origin 分别是精确 Sites Production、localhost 和其他站点

**When** 标的、当前行情、日内条形、USD/CNY 或 AI client 构造请求

**Then** 只有精确 Sites origin 使用 `https://provider.example.com`；localhost 与 Vercel legacy 使用同源相对路径，其他 origin 不会被自动视为可信 Sites。

### AC-PROXY-02：跨域权限最小化

**Given** Vercel provider 收到 preflight 或实际请求

**When** `Origin` 为精确 Sites origin、攻击者 origin 或缺失

**Then** 只对精确 Sites origin 返回对应 GET/POST/OPTIONS、`Content-Type`、`Vary: Origin` 和该精确 `Access-Control-Allow-Origin`；不返回 `*` 或 credentials，攻击者 origin 在上游调用前被拒绝。Sites CSP `connect-src` 只允许 `'self'` 和该 Vercel origin。

### AC-PROXY-03：provider 故障不写 D1

**Given** Vercel、Alpaca、ECB 或 DeepSeek 超时、限流或返回无效响应

**When** Sites 正在刷新行情、汇率或执行用户主动触发的 AI 请求

**Then** 页面使用既有缺价/上一有效缓存/可重试错误降级；Vercel 不接收 `/api/portfolio`、D1 revision、草稿、历史库或 JSON 文件，账号 current 零变化。

## 2. 启动与统一录入

### AC-UI-01：无需券商设置即可开始

**Then** 前三个时段使用 `feed=delayed_sip` 与 `LATEST_TRADE`；隔夜使用 `feed=overnight` 与 `INDICATIVE_TRADE`，页面级只标注一次约 15 分钟延迟，持仓行不显示时段、feed 或隔夜提醒

### AC-QT-12：隔夜无成交安全回退

**Given** 当前处于有效隔夜时段，但某标的的 `overnight` Snapshot 暂无成交
**When** 系统完成刷新
**Then** 该标的回退到最近的 `delayed_sip` 或上一有效价，在数据层保留真实事件时间和价格类型，不显示 `0`，也不把回退价伪装成新的隔夜成交；首页不显示逐行回退提醒

### AC-QT-13：前台持续跟随

**Given** PWA 保持前台可见
**When** 市场时段持续变化
**Then** App 每 60 秒发起一次非重叠刷新，并在从后台恢复时立即补刷；被 iOS 暂停或关闭期间不承诺后台刷新

### AC-QT-14：所有行情状态都不生成独立汇总卡

**Given** 组合包含健康、轻度老化、过期、上一有效价、缺价或异常行情
**When** 用户查看首页
**Then** 页面不显示独立行情汇总卡；页面级只披露一次约 15 分钟延迟；持仓行不显示逐行时段、日期时间、老化、上一有效价或隔夜提醒，缺价仍明确显示，请求故障只使用紧凑错误提示

## 8. JSON 数据副本与空组合恢复

### AC-BACKUP-01：导出当前活动快照

**Given** Sites 账号中有旧 positions/cash current 或 v4 broker book，并可能同时保留 previous

**When** 用户从“更多操作”点击“导出数据副本”

**Then** 旧 current 导出 JSON v2，每个股票只包含当前活动 `PositionSnapshot`，`cash` 只包含当前 `CashSnapshot` 或 `null`；v4 导出 JSON v3，只包含 current book 与当前维护事件。两种格式都保留十进制字符串真值，不包含 previous、草稿或缓存

### AC-BACKUP-02：不混入内部数据

**Given** 当前来源同时存在上一版本、持仓草稿、录入页草稿、上一有效行情缓存、legacy 券商备份、outbox 或同步游标

**When** 解析导出的 JSON

**Then** 上述内部数据都不在文件中，文件也不包含 API key、token、认证信息或派生展示缓存

### AC-BACKUP-03：十进制保持字符串

**Given** 当前输入包含数量 `0.125`、成本 `25.10` 和现金余额 `20000.50`

**When** 序列化并重新解析 JSON 文件

**Then** 三个值仍是十进制字符串，没有转成 JSON number，也没有被展示舍入值覆盖

### AC-BACKUP-04：导出只读

**Given** 用户导出前记录了股票与现金的当前快照、上一版本、股票草稿和 revision

**When** 导出成功、用户取消系统分享、文件分享失败或生成失败

**Then** Sites D1 账号 state 与本机草稿/缓存都与导出前完全一致，没有新增活动版本、state revision、schema 升级、清空或覆盖

### AC-BACKUP-05：文件交付与回退

**Given** 浏览器支持通过 Web Share 分享文件

**When** 用户发起导出

**Then** 系统优先分享 `application/json` 文件；若浏览器不支持文件分享或发生非取消型分享失败，则使用同名 Blob 下载回退；用户主动取消分享时不再额外下载

### AC-BACKUP-06：重复操作

**Given** 一次导出仍在生成

**When** 用户重复点击“导出数据副本”

**Then** 按钮保持禁用且不会启动第二次导出

### AC-BACKUP-07：限制说明准确

**Given** JSON 文件已经生成

**When** 用户查看成功提示和隐私说明

**Then** 页面提示确认文件已存到“文件”或用户选择的目标，说明文件包含持仓数量、成本和 IBKR 现金记录；最近生成时间不被写成已保存证明，页面只承诺本节定义的空组合 current-only 恢复，不声称自动备份、云备份、完整设备恢复或跨设备恢复

### AC-BACKUP-08：不上传 provider 后端

**Given** 用户在生产来源生成 JSON

**When** 检查导出动作的应用网络请求和服务端日志

**Then** 没有向 Vercel provider 发送持仓文件或其内容的上传请求；Vercel 不能读取 Sites D1 current 或本机 IndexedDB，只有用户主动触发的 AI 请求会按 ADR-042 携带 current-only 快照

### AC-RESTORE-01：严格拒绝无效文档

**Given** 用户分别选择无效 JSON、未知 `format`、非 v2/v3、字段缺失或多余、非法十进制/时间/源 revision、不受支持的市场/币种/symbol、同一规范标的重复、同一规范 symbol 跨多个受支持市场，或现金/book contract 不合法的文件

**When** App 在本机解析恢复文件

**Then** 每个文件都在写事务前被拒绝，显示可理解且不回显整份私人文件的错误；股票、现金、previous、草稿与缓存均不改变

### AC-RESTORE-02：写入前预览 current 数据

**Given** 用户选择一个有效且非空的 JSON v2 或 v3

**When** 严格解析成功

**Then** 页面在确认按钮之前显示导出时间、股票/输入数量、数量与剩余成本，以及现金或 v4 book 摘要；说明只把规范化 current 恢复到当前登录账号，源 revision 不继承，原始文件、历史、草稿和缓存不进入 D1

### AC-RESTORE-03：只接受完全空目标

**Given** 账号 positions、cash 或 broker current 任一非空

**When** 用户尝试确认恢复

**Then** 整次恢复被拒绝，不提供合并、覆盖或按标的选择，账号 state 逐字段保持不变

### AC-RESTORE-04：全 current 单次 D1 CAS 成功

**Given** 账号 positions/cash/broker 全空，文件包含有效 v2 current 或 v3 book

**When** 用户核对预览并完成第二次确认

**Then** Sites 服务端重验文档，在同一次 D1 CAS 内再次确认账号全 current 为空并写入规范化 state；刷新或同账号换设备后读到 `revision=1`、`nextRevision=2`、`previous=null` 的新 current，源 revision 只被校验，不成为账号 revision

### AC-RESTORE-05：任一失败零写入

**Given** 空账号恢复在服务端校验、D1 CAS 竞争或持久化任一阶段失败

**When** 事务中止

**Then** 账号 positions/cash/broker 都仍为空，页面明确说明没有写入任何资产，最近成功恢复时间不更新

### AC-RESTORE-06：并发恢复最多一个成功

**Given** 两个页面几乎同时对同一空账号确认恢复

**When** 两个操作都进入 repository

**Then** D1 `state_version` CAS 只允许一个完整成功；另一个以 409/目标非空拒绝，最终没有重复或被覆盖的账号资产

### AC-RESTORE-07：恢复范围严格 current-only

**Given** 有效 v2/v3 文件只含 contract 允许的 current 资产，而浏览器还存在草稿、行情/汇率缓存、legacy backup、outbox 或同步状态

**When** 恢复成功

**Then** 只在 D1 新增规范化 current；上述设备内非目标数据既不从文件创建，也不因恢复被清空或改写。原始文件不持久化，Vercel provider 不接收文件

### AC-RESTORE-08：空文件、取消与存储提示诚实

**Given** 用户选择有效但没有股票和现金的空备份，或在预览/二次确认时取消

**When** 流程结束

**Then** 不开启资产写入或更新成功时间；持久存储状态与最近生成时间只作为设备风险提示，不被表述为已经保存外部副本或完成恢复。`persisted()`、`persist()` 或属性读取抛错时显示“无法确认”，不能显示为已拒绝或未授予；只有 API 明确返回 `false` 才显示尽力保存

## 9. 复制持仓资料到剪贴板或 ChatGPT

### AC-COPY-01：范围与排序

**Given** 当前组合有 11 只股票和一条 IBKR 现金，部分股票市值相同且至少一只缺价

**When** 用户从“更多操作”查看“持仓资料”分组

**Then** 同时显示“仅复制持仓资料”和“复制并打开 ChatGPT”；任一入口打开后都显示前 5、前 10、全部资产和选择单只。前 5/前 10 只按未舍入股票市值降序，同值先按代码、再按规范标的键稳定排序，缺价置后；全部资产同时包含 IBKR 现金，组合不超过 5 或 10 只股票时不显示与全部重复的范围

### AC-COPY-02：单只包含必要组合背景

**Given** 用户选择一只已定价持仓

**When** 生成单只文本

**Then** 文本包含低噪音组合摘要，并在唯一持仓表行中给出该标的数量、均价、估值、市值、盈亏、收益率、占已计价总资产比例和股票市值排名；分母包含现金本金，但不展开其他股票明细或逐股排障元数据

### AC-COPY-03：AI 所需字段完整且排障噪音受控

**Given** 当前持仓同时包含新延迟行情和上一有效价

**When** 生成任一复制范围

**Then** 文本包含 USD 分钟级生成时间、组合级 Alpaca 延迟/非实时说明和价格时间范围；组合摘要包含资产、股票定价数量、必要的成本/盈亏、现金/仓位和范围覆盖，持仓表包含排名、标的、数量、均价、现价、市值、盈亏、收益率和仓位；上一有效价用 `*` 标记，隔夜指示价用 `†` 标记；文本不逐股展开 provider、feed、市场时段、行情状态、价格类型、事件时间或获取时间。全部资产还紧凑包含现金 NAV 与来源、Pro/Lite、免息额、计息余额、公布/NAV 调整/整笔利率、年/月利息估算和核验日

### AC-COPY-04：缺价不归零

**Given** 一只持仓从未取得有效价格

**When** 复制包含该持仓的范围

**Then** 估值价写“暂无有效价格”，市值、盈亏、收益率、权重和排名写“无法计算”，不得出现由缺价制造的 `$0.00`

### AC-COPY-05：同一用户动作与同一文本

**Given** 页面由 HTTPS 提供且用户点击一个具体复制范围

**When** 浏览器支持系统剪贴板

**Then** 系统只生成一次范围文本。普通复制只调用 `writeText()` 并留在当前 PWA，不构造或打开 ChatGPT URL；ChatGPT 路径的 `writeText()` 在任何异步等待前调用，URL 的 `prompt` 解码后与该文本逐字符相同。任一目标写入不可用或被拒绝时都保留相同内容的只读文本框，且不重新读取或重新生成资料

### AC-COPY-06：只读与外部数据边界

**Given** 用户记录了复制前的所有股票/现金当前快照、历史防护版本、股票草稿、行情缓存和 schema

**When** 自动复制成功、失败或进入手工回退

**Then** 上述本地数据完全不变，两个目标都没有行情请求、repository 读取、本产品持仓上传请求或 OpenAI API 调用，服务端日志不包含复制文本。普通复制没有外部导航；只有 ChatGPT 路径把编码后的 Prompt 交给 `chatgpt.com`，完整 URL 不进入日志，界面不得把该路径描述为“完全不上传”

### AC-COPY-07：待发送且不调用 API

**Given** 已生成复制文本

**When** 检查文本和页面行为

**Then** 文本只陈述数据，不包含“请分析”等预设提问或买卖建议。普通复制停留在 PWA 且不调用分享面板；ChatGPT 目标通过 `https://chatgpt.com/?prompt=<百分号编码文本>` 打开 App 或网页，Prompt 停在输入框等待手动发送。两者都不自动发送、不调用 OpenAI API、不持有 ChatGPT token、不接收回答，也不生成图片

### AC-COPY-08：单只快捷入口与可访问性

**Given** 用户通过点按、长按、右键、Enter、Space 或辅助技术打开某只持仓菜单

**When** 分别选择“仅复制这只持仓资料”和“复制并打开 ChatGPT”

**Then** 两条路径的范围都只包含该标的及组合摘要，文本逐字符相同；普通复制留在 PWA，ChatGPT 路径进入待发送 Prompt。生成期间阻止重复操作，完成或关闭回退后焦点返回原触发元素

### AC-COPY-09：所有范围都支持两个目标

**Given** 当前组合足以显示前 5、前 10、全部和选择单只四类入口

**When** 用户分别从普通复制和 ChatGPT 入口完成每一类最终选择

**Then** 四类范围在两个目标中都使用同一文本生成器；普通复制执行“生成 → 剪贴板 → 留在 PWA”，ChatGPT 执行“生成 → 剪贴板 → 待发送 Prompt”。范围菜单和股票操作菜单传递明确目标，不能因上一次选择串用目标

### AC-COPY-10：App、网页与手工回退

**Given** 使用合成的短文本、中文换行文本和接近实际全部持仓长度的长文本

**When** 分别在 ChatGPT App 已安装并接管、未接管而打开网页、未登录、预填缺失或文本被截断的条件下执行复制

**Then** 已接管路径打开 App，未接管路径留在官方 ChatGPT 网页；能预填时均保持待发送且内容完整。不能可靠预填时不误报已发送或完整，剪贴板或只读文本允许用户手工粘贴。验证证据不保存真实持仓、完整 Prompt URL 或 ChatGPT 登录资料

### AC-COPY-11：成功反馈为短暂 Toast

**Given** 任一目标的复制范围返回 `delivery=copied`

**When** PWA 页面可见或用户从 ChatGPT 返回 PWA

**Then** 普通复制的 `role=status` Toast 显示“已复制，可粘贴到其他应用”，ChatGPT 路径显示“已复制并打开 ChatGPT”；两者均不占布局、不获取焦点，总览与持仓列表之间没有成功文案，约 2.4 秒后自动移除。`manual-fallback` 不显示成功 Toast，并进入目标专属手工复制弹层

### AC-COPY-12：普通复制失败文案不混入 ChatGPT

**Given** 用户从“仅复制持仓资料”选择任一范围且系统剪贴板写入失败

**When** 展示手工复制回退

**Then** 弹层说明“系统未能自动写入剪贴板”，提供同一文本的只读输入；不得出现“已尝试打开 ChatGPT”、Prompt、预填或外部导航文案，也不得发生 ChatGPT URL 构造或导航

## 10. USD / 人民币显示模式

### AC-FX-01：整页同步切换

**Given** 首页有已定价股票、IBKR 现金和一笔有效 `USDCNY` 汇率

**When** 用户点击“人民币”

**Then** 总览标题与金额、2 × 2 核心指标中的股票成本、现金本金、累计盈亏与今日盈亏金额、现金余额与年/月利息估算及股票表金额全部切换为 `¥` 人民币估算；数量、股票收益率、今日涨跌幅和现金利率保持原值，NAV 明确保留 USD 口径

### AC-FX-02：使用未舍入 USD 真值

**Given** 未舍入 USD 金额为 `1000.005`，`USDCNY` 中间价为 `7.2`

**When** 生成人民币 ViewModel

**Then** 先计算 `1000.005 × 7.2 = 7200.036`，再显示 `¥7,200.04`；不得先把 USD 显示为 `$1,000.01` 后再换算

### AC-FX-03：汇率 contract 与来源披露

**Given** Alpaca 返回 `USDCNY` midpoint，或 Alpaca 不可用而欧洲央行返回同一参考日的 USD/EUR 与 CNY/EUR 日参考价

**When** 服务端汇率路由和首页消费该响应

**Then** 浏览器取得十进制字符串 rate、USD→CNY 方向、合法的 `alpaca + MIDPOINT` 或 `ecb + REFERENCE`、`sourceEventAt` 和 `fetchedAt`；ECB 结果同时包含 `referenceDate`。人民币模式显示“人民币估算”和实际来源；Alpaca 显示中间价与汇率时间，ECB 显示日参考汇率、参考日和官方更新时间，任何结果都不称为实时汇率

### AC-FX-04：上一有效汇率与过期边界

**Given** Alpaca 与欧洲央行在线汇率刷新均失败

**Given** 服务端向 Alpaca 请求当日条形

**Then** 参数固定为 `feed=sip`、`timeframe=15Min`、`adjustment=split`、`currency=USD`，`availableThrough` 不晚于服务端当前时间减 15 分钟，响应保留 provider、feed、周期、复权、延迟策略和窗口时间

### AC-TREND-03：当前数量与现金口径正确

**Given** 每只股票有当前数量、前收与真实日内条形，且组合有现金
**When** 派生时点 `t`
**Then** 今日价格影响等于 `Σ[Q×(P(t)-C)]`，涨跌幅分母等于 `Σ(Q×C)`；现金本金只加入该点估算总资产，不加入今日价格影响或涨跌幅分母

### AC-TREND-04：多标的错位条形不插值

**Given** 两只股票的真实条形时间不同
**When** 系统合成时间轴
**Then** 时间轴使用真实事件时间并集；没有新条形的标的只保持上一已知真实价，不在两个点间创造价格

### AC-TREND-05：缺失和纯现金不画假线

**Given** 组合缺少任一前收、series 缺失/失败、可读时点不足，或组合只有现金
**When** 首页渲染趋势区
**Then** 显示对应的暂无走势说明，不使用 `0`、成本、直线、随机数或插值画线

### AC-TREND-06：只有今日范围

**Given** 首页已载入趋势区
**When** 用户查看趋势
**Then** 只显示由当前数量与 SIP 条形估算的“今日走势”，不在趋势图下重复计算口径小字，不渲染 `1W / 1M / 3M / 1Y / ALL`、长期不可用占位或历史入口，也不以当前数量回套长期价格

### AC-TREND-07：USD 真值与 CNY 派生

**Given** 趋势有未舍入 USD 金额点且有有效 USD/CNY 汇率
**When** 用户切换为人民币
**Then** 每点金额由未舍入 USD 值乘同一汇率后展示，涨跌幅不变，不写回趋势、持仓或汇率真值

### AC-TREND-08：隔夜点不伪连线

**Given** 当前实现没有接入真实 `overnight` 趋势点
**When** SIP Historical Bars 结束于盘后
**Then** 不从 SIP 尾点插值或连线到当前快照价；以后接入时也只能用真实时间与完整覆盖的独立点

### AC-TREND-09：趋势只读且故障隔离

**Given** 用户刷新、探查或趋势请求失败
**When** 检查 D1 账号 current、旧 Vercel IndexedDB、当前快照、行情/汇率缓存和 JSON 副本
**Then** 趋势未持久化，任一上述真值都不改变；趋势错误不清空已有估值或持仓

### AC-TREND-10：高级首页层级与移动交互

**Given** 页面宽度为 320、390 或 430 CSS px，或用户使用键盘/减少动效
**When** 查看总资产并探查趋势
**Then** 总资产、今日变化、曲线和 2 × 2 指标位于一个连续纯黑英雄区，不裁切或造成页面主体横向滚动；指针可横向探查且不阻断纵向滚动，方向键/Home/End 可访问真实点，数值不只靠颜色或动画表达

## 14A. 双券商 current、买入与卖出

### AC-BROKER-01：首次校准不猜来源或改写旧 current

**Given** 旧 v3 有聚合股票与可选 IBKR 现金，且没有 v4 book
**When** 用户打开双券商校准页、填写 IBKR/moomoo 当前值并在预览后二次确认
**Then** 只新增 `broker_portfolio_v4` current；旧股票、旧现金、previous、草稿、legacy、行情与汇率逐字段不变。确认前或失败时 v4 不存在。

### AC-BROKER-02：统一股票与统一组合现金投影

**Given** 同一股票同时存在 IBKR 与 moomoo 子持仓，两边均有现金
**When** 首页读取 v4 book
**Then** 股票仍只显示一行，数量和成本分别求和后计算均价；现金只显示一条由全部 settled/pending 分量求和的“组合现金”，不显示两个可分别花用的现金池，旧 store 不作为活动资产读取。

### AC-BROKER-03：任意股票买入扣减组合现金

**Given** v4 book 已校准
**When** 用户在 moomoo 买入碎股并填写成交均价、手续费和现金状态
**Then** 只增加 moomoo 该股数量与 `gross + fee` 成本，组合现金准确减少 `gross + fee`；来源以外的股票字段不变，首页重新合并。把标的换成 BOXX、SGOV、AAPL 或其他受支持股票时公式不变。

### AC-BROKER-04：部分卖出使用券商移动平均成本

**Given** 所选券商持有数量 `Q`、剩余成本 `C`
**When** 卖出 `q < Q`
**Then** 剩余数量为 `Q-q`，剩余成本为 `C×(Q-q)/Q`，组合现金增加 `q×price-fee`；另一券商同股数量与成本不变，现金来源分量不作为用户可见独立池。

### AC-BROKER-05：全卖只移除所选券商

**Given** 两家券商都持有同一股票
**When** 一家券商卖出其全部数量
**Then** 只移除该券商子持仓；另一家仍保留，首页合并行不消失。两家都为零后才无该股票投影。

### AC-BROKER-06：超卖、重复和并发冲突零变化

**Given** v4 current revision 与已有 event id
**When** 卖出超过所选券商数量、重复提交同一 id，或用 stale revision 保存
**Then** 整笔拒绝；来源持仓、双现金、events、current/previous 都不出现部分更新。

### AC-BROKER-07：已结算、待结算和负现金诚实展示

**Given** 买卖产生正/负 pending 或使 settled/book cash 为负
**When** 首页、复制、CNY 与组合结构读取现金
**Then** `settled + pending` 进入总资产并保留正负；待结算单独显示，负值标为融资负债，不回退为零。

### AC-BROKER-08：IBKR 利息只使用正已结算余额

**Given** IBKR 同时有 settled/pending，moomoo 有现金
**When** 生成利息估算
**Then** 只有正 IBKR settled 进入 ADR-023 公式；pending、moomoo 与负余额排除。fallback NAV 随 SETTLED 交易同步为非负已结算余额。

### AC-BROKER-09：重复校准提供当前值恢复路径

**Given** v4 已有交易，但用户发现遗漏交易、现金流、转账或券商成本差异
**When** 再次校准并确认
**Then** 新 current 完整替换来源持仓与双现金，previous 保留上一成功 book，并新增 RECONCILIATION 事件；不生成长期收益。

### AC-BROKER-10：旧写入路径在 v4 启用后退出

**Given** v4 current 已存在
**When** 用户点击底部录入、股票操作，或直接打开 `/positions/new`、`/cash`
**Then** 使用 `/trades/new` 或 `/portfolio-setup`；旧股票/现金 store 不被写入，统一行不提供直接删除。

### AC-BROKER-11：JSON v3 严格导出与三 store 空目标恢复

**Given** v4 current 存在
**When** 用户导出、选择并恢复 JSON v3
**Then** 导出只含严格 current book 与事件；恢复前预览来源分项、数量、成本和双现金。只有旧股票、旧现金、v4 book 全空时写 revision 1 / previous null；任一非空或失败零写入。

### AC-BROKER-12：AI 与复制使用统一现金和来源明细

**Given** v4 双现金存在
**When** 用户复制全部资产或主动触发 AI
**Then** 总资产和现金权重使用两家账面现金合计；资料列出两边 settled/pending，AI context 使用 `PORTFOLIO` cash 与 IBKR/moomoo accounts，IBKR 利息独立且不把总现金冒充 IBKR 余额。

### AC-BROKER-13：交易预览只使用组合现金

**Given** IBKR 与 moomoo 内部分量合计为 `portfolioCashBefore`
**When** 用户预览任意股票的 BUY 或 SELL
**Then** 预览只显示一条组合现金前后值；BUY 为 `before-gross-fee`，SELL 为 `before+gross-fee`。保存后结果逐字匹配预览；取消、失败或冲突时组合现金与股票都不变。

## 15. 十进制与密钥安全

### AC-NF-01：十进制确定性

**Given** 领域黄金样例在受支持环境执行  
**When** 重复计算 100 次  
**Then** 未舍入结果完全一致，展示结果符合统一舍入规则

### AC-SEC-01：Alpaca 密钥仅服务端可见

**Given** 客户端构建、源码映射、网络响应和浏览器存储可被检查  
**When** 执行密钥扫描  
**Then** 不存在 Alpaca API key、secret 或其他 server-only 凭据

### AC-SEC-02：DeepSeek 服务端边界受控

**Given** AI 路由部署在公开 Vercel Production
**When** 检查构建、请求和故障路径
**Then** `DEEPSEEK_API_KEY` 不进入浏览器或响应；上游固定官方 HTTPS origin 并拒绝重定向，请求受大小限制、超时、尽力限流、`no-store` 与 kill switch 约束，生产账户另有受控余额作为硬费用边界

### AC-SEC-03：客户端不包含固定个人资产载荷

**Given** 检查待发布源码和 Production 客户端构建产物

**When** 扫描旧启动模块、标记、固定持仓/现金数值与 Controller 引用

**Then** 运行源码和客户端 bundle 均不包含可用于还原该个人组合的载荷或自动恢复路径；历史 ADR 可保留决策记录，不得进入构建运行图。

### AC-SEC-04：公开 API 有一致的资源消耗边界

**Given** 任一标的、行情、当日条形、汇率或 AI 能力路由收到跨站浏览器请求、错误 Content-Type、声明或实际超限请求、额外字段、重复/歧义标的或超频调用

**When** 请求到达服务端或上游返回越界响应

**Then** 系统在调用付费或受配额上游前返回安全的 `403/413/415/429` 或 contract 错误；调用方只以截断哈希进入有界单实例 bucket，响应不含密钥、原始 IP 或上游 body。跨实例保护由已启用的 Vercel WAF/Bot Protection 和 provider 硬预算验证。

**And** 对固定 Sites origin 的五个跨域 provider 路由仍执行同一字节、字段、频率、上游 origin、重定向、超时和响应大小约束；精确 CORS 不豁免其他检查。

### AC-SEC-05：浏览器与发布链有纵深保护

**Given** Sites source saved version/private deployment 是用户页面与 D1 client 的供应链，GitHub `main`/Vercel deployment 是 provider 与公开静态资产的供应链

**When** 检查生产响应、构建产物和仓库安全设置

**Then** Sites 发布包与 Vercel provider 响应都有对应 CSP/HSTS/跨源/点击劫持/MIME 防护；Sites 只以已验证 source commit 保存 version 并 owner-only 发布，Vercel 只以通过 GitHub 安全门禁的 `main` commit 发布 provider。任一运行时门禁失败，都不得把对应 deployment 声明为合格。

### AC-NF-02：provider 可替换测试

**Given** 测试环境不访问真实行情网络  
**When** 使用 fixture provider 运行健康、陈旧、异常和失败场景  
**Then** 领域与 UI 状态测试确定性完成，不依赖真实 provider 波动

## 16. 明确未验收

下列能力不得因现有底层代码或旧文档存在而被声明为产品完成：

- 已实现盈亏、税务成本或卖出批次；
- 长期组合收益、券商历史导入、自动交易或券商 API；
- 跨账号共享、自动合并、自动版本化云备份；
- 真实第二设备同账号读取与并发冲突真机闭环（代码和本地 D1 证据已建立，Production 仍需 smoke）；
- Service Worker、完整离线应用壳和离线编辑；
- 非 v2/v3 JSON 迁移、向已有账号组合合并或覆盖、自动/云备份、隐私模式；

上述能力只有在产品所有者确认范围、PRD 更新并新增对应 Given/When/Then 场景后，才进入验收。
