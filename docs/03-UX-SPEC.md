## 1. 已确认体验

- 用户打开产品后直接面对一个统一组合，不先创建或选择券商。
- 所有持仓从同一个入口录入。
- 来自两处的相同标的合并成一条持仓。
- 首页第一屏让用户直观看到合并后的总仓位。
- P0 按标的录入当前持仓快照；同一标的可以有多组数量与成本。
- 成本录入同时支持平均成本和剩余总成本两种模式。
- 普通录入入口遇到已有标的时，本次输入自动叠加到当前批次，页面直接展示保存后的合并数量、总成本和均价。
- 点按或长按股票持仓打开同一“修改持仓、加仓、仅复制这只持仓资料、复制并打开 ChatGPT、删除持仓”菜单；长按作为快捷方式保留，横滑后不得误触。

## 2. 体验原则

1. **先看总仓位。** 第一屏优先呈现组合结果，不用设置页、资讯或图表抢占注意力。
2. **录入只有一个入口。** 用户无需理解数据模型或来源分组。
3. **同标的只出现一次。** 合并结果是默认视图。
4. **只保留会改变资产判断的信息。** 约 15 分钟延迟在页面级只说明一次；列表省略时段、日期时间和老化标签，只标记缺价，请求故障使用紧凑提示。
5. **精简显示不改变行情真值。** 使用上一有效价时在数据层保留原时间，不回退为 `0`，也不把旧价伪装成新价。
6. **输入失败可恢复。** 校验或保存失败不能清空已填写内容。
7. **红涨绿跌，颜色只作辅助。** 正收益与正盈亏使用红色，负收益与负盈亏使用绿色；正负和状态同时使用符号、文字或图标表达。
8. **导出只复制。** 生成、取消或保存 JSON 副本都不能修改账号 D1 current。
9. **先选目标，同一文本。** 普通复制与 ChatGPT 入口的范围、剪贴板和手工回退都复用当前页面内存生成的同一份文本，不修改持仓。普通复制留在 PWA；只有 ChatGPT 入口会把编码后的 Prompt 交给 `chatgpt.com`，并保持待发送。
10. **币种切换只改变显示。** 人民币模式使用同一笔有效汇率折算金额并说明实际 provider、rate type、参考日或来源时间；录入、备份、复制和持仓真值继续使用 USD。
11. **现金操作与股票隔离。** 录入、修改或删除 IBKR 现金只改变独立现金记录；失败时保留表单和已有股票，删除必须二次确认。
12. **今日盈亏是全股票仓的价格影响估算。** 使用当前股数乘以相对最近常规收盘的价格变化，现金不参与；当日买卖造成股数变化时，不把该值表述为券商按真实交易流水计算的当日盈亏。
13. **恢复先证明安全再写入。** 文件先在当前设备严格校验和预览；只有账号股票、现金与 v4 book 都为空且用户二次确认时，才通过单次 D1 CAS 原子写入，不提供合并或覆盖。
14. **洞察必须披露分母与完整性。** 结构只覆盖已定价股票与现金；今日净额要求全量，绝对贡献可描述可计算子集，但缺失和零分母不能伪装成 `0%`。
15. **统一展示不等于丢失资金来源。** 股票行按标的合并；卖出可用数量、剩余成本和现金只在所选券商子账本中变化。
16. **校准先预览，股票与组合现金同成败。** 旧聚合值只作对照；确认前不建立 v4。任意股票 BUY/SELL 保存前显示来源股数与组合现金前后值，失败时两者均不变。
15. **首页只表达今日走势。** 唯一曲线只用真实 SIP 条形与当前快照；不显示长期档位、历史占位或导入入口，缺数据时显示暂无走势。
16. **AI 入口分离、触发清楚。** 点按“组合分析”直接开始体检；打开“巴菲特框架顾问”不请求，只有发送问题才建立当前完整 USD 固定快照。两个能力使用独立弹层，主路径保持低噪音；AI 分类标明为推断，缺少真源的高级指标标明不可计算，任何不合规输出整份拒绝。

## 3. 最小信息架构

首版有股票快照、现金和双券商 book 的账号修改路径，以及首页只读交付操作：

```text
ChatGPT 登录 ──> owner-only Sites ──> 账号 D1 current
持仓首页 ──> 当前持仓快照
    ^            │
    └────保存────┘

持仓首页 ──> 数据安全与恢复 ──导出──> 系统分享 / 本地 JSON 下载
                              └─空目标恢复──> 股票与现金 current
持仓首页 ──仅复制──> 系统剪贴板 / 手工复制文本（留在 PWA）
        └─复制并打开 ChatGPT──> 系统剪贴板
                              └─HTTPS Prompt──> ChatGPT App / 网页（待发送）

        └─巴菲特框架顾问──打开零请求──发送问题──> DeepSeek 连续问答（固定首次发送快照，仅当前内存）
```

## 4. 空组合与首次录入

### 4.1 空组合

必须显示：

- 标题：“还没有资产”
- 说明：“录入股票或 IBKR 现金后，这里会合并显示总资产。”
- 底部唯一主按钮：“录入资产”；点按后选择“录入股票”或“录入 IBKR 现金”

不得显示：

- 券商设置步骤或“管理券商”按钮；
- 一排容易被误解为完整结果的 `$0.00`；
- 跨账号共享、自动迁移旧 origin 或完整离线承诺。

### 4.2 统一录入

P0 表单最少包含：

- 可解析的股票或 ETF 标的；
- 持有数量；
- 成本模式：平均成本或剩余总成本；
- 对应成本值。

交互要求：

- 不出现券商字段。
- 使用独立全屏页面，避免 iPhone 键盘与底部弹层互相遮挡。
- 用户停止输入有效股票代码约 0.5 秒后自动发起 Alpaca 解析；不提供前置“验证标的”按钮。
- 自动显示 Alpaca 返回的股票名称和上市市场；上市市场不可编辑，用户无需理解或选择交易所代码。
- 币种固定为 USD，不显示币种字段或选择器。
- 保存前确认代码、名称、上市市场与 USD 标的身份；不支持或无法解析的标的不能保存。
- 同一标的可以增加多组数量与成本行。
- 普通录入已有标的时，不要求用户先载入并重填旧输入；页面保留本次输入，同时读取当前批次参与合并预览。
- 数量和成本使用十进制文本输入，不通过二进制浮点数改写真值。
- 成本模式切换只改变输入解释与表单字段，不能用展示舍入值改写真值。
- 字段错误紧邻对应输入显示，并保留其他有效输入。
- 保存前显示该标的最终活动批次的合并数量、总成本和平均成本预览。
- 普通录入已有标的时，同时说明“当前持仓”“本次输入”和“保存后合并结果”，主操作写“叠加并保存”。

- 普通录入的“叠加”表示增加当前持仓分项，不能写成“追加买入”或交易记录。
- 提交期间防止重复操作。
- 保存失败时保留整张表单。
- 叠加或替换成功后回到首页，只显示一条该标的合并持仓；首页不显示历史版本恢复入口。

### 5.3 合并持仓列表

每行固定显示：

- 第一列：股票名称与代码；
- 第二列：市值与合并数量；
- 第三列：估值价与合并平均成本；
- 第四列固定显示浮动盈亏与浮动持仓收益率；
- 第五列主值显示逐股今日涨幅，下方小字显示带正负号的逐股今日盈亏金额；股票行不重复“估算”文案，缺少有效估值价或最近常规收盘价时显示 `— / 暂无`；
- 正收益率和正盈亏使用红色，负收益率和负盈亏使用绿色；正负号继续保留。

整张持仓表只使用一个横向滚动容器：表头、全部股票行和现金行共享 `scrollLeft`。第一列固定，后四列从其下方移动。横向移动超过阈值时同时取消待触发长按并抑制随后的点击；纵向手势继续滚动页面。

2 × 2 核心指标中的“今日盈亏”主值显示带正负号的全股票仓估算金额，副值显示组合涨跌幅和“估算”；不增加独立详情入口或模式切换。

今日盈亏按当前股数相对最近常规收盘价估算：组合只有在全部股票都具备有效估值价和常规收盘参考时才显示金额与涨跌幅；任一字段缺失时两者显示 `—`，不得用 `0` 补齐。IBKR USD 现金本金、NAV 和利息估算不参与分子或分母。正值用红色、负值用绿色，正负号和“估算”文案必须保留。

约 15 分钟延迟在列表页面级只披露一次。市场时段、行情日期时间、偏旧、过期、上一有效价或隔夜提醒不进入持仓行；从未取得有效价格时显示“暂无价格”，请求故障使用紧凑的页面级提示。

`[实现事实 2026-08-02]` 持仓表右侧固定百分比是：

```text
(marketValue - totalOpenCost) / totalOpenCost
```

它表示浮动持仓收益率。总资产指标矩阵中的今日盈亏使用相对最近常规收盘价的组合价格变化金额与涨跌幅，两种口径不得混用；行情仍为约 15 分钟延迟，也不得写成“实时盈亏”。

不同标的保持独立。相同规范标的只能出现一次。

标准 iPhone 宽度、极窄容器和文字放大状态均保持五列与细分隔线，不再压缩五列或改成两列卡片。持仓表使用稳定最小宽度并在自身内部横向滚动；页面主体、总资产区、说明和底部操作不得产生非预期横向滚动。初始位置应露出后续数据列，横滑终点必须完整显示第五列百分比与小字金额。

点按或长按持仓行打开同一底部操作菜单：

- “修改持仓”：显示当前合并数量与合并均价；
- “加仓”：填写本次增加数量与买入均价；
- “删除持仓”：进入第二次确认，明确说明无法撤销且其他股票不受影响；
- “取消”：关闭菜单并把焦点返回原持仓行。

持仓区轻量提示“左右滑动 · 点按股票操作”。键盘 Enter/Space、桌面右键和辅助技术必须能打开同一菜单。

`[建议]` 默认按持仓市值从高到低；没有有效价格的标的排在末尾并明确标记。

### 5.4 IBKR USD 现金

- 现金行位于股票行之后并共用五列宽度；每个数据单元格内明示现金专属标签：“现金余额、NAV 调整利率、估算年利息、今日变化”。

- 现金表单依次显示 USD 余额、Pro/Lite 选择和可选 IBKR NAV；在有效输入后即时显示计息余额、NAV 调整利率、整笔混合利率、年利息和月均利息。
- NAV 帮助文案说明它是 IBKR 账户净资产；留空时明确写“暂按现金余额估算”，不使用本 App 其他股票自动补齐。
- 规则区显示首 USD 10,000 不计息、NAV 低于 USD 100,000 时降档、IBKR 官方链接和核验日。预览与首页都使用“估算”，不使用“保证”或“固定收益”。
- 修改页底部提供“删除现金记录”；点击后再显示取消与“确认删除”，并明确股票持仓不受影响。

### 5.4A 双券商启用后的股票与现金

- 首页 2 × 2“现金”格和连续表中的单条“组合现金”行都显示 IBKR + moomoo 内部分量合计。该行明确“买入扣减、卖出增加”，不把分量展示成两个可分别花用的现金池；负合计标为融资负债。
- 组合现金行不把总额冒充 IBKR 计息余额；可用时只在说明区展示正 IBKR 已结算分量对应的 NAV 调整利率与估算年息，待结算和其他内部分量不参与。
- 股票菜单把旧“修改持仓/加仓/删除”替换为“买入/卖出/校准持仓”；复制目标保持。全卖只能通过 SELL，不能直接删除统一行。
- 交易券商使用 IBKR/moomoo 二选一分段控件。卖出选择券商后立即显示该券商可卖数量和剩余成本，超量时阻止保存。
- 现金状态默认“待结算”，也可选择“已结算”。预览必须同时显示成交总额、现金变化、来源券商股数前后值与组合现金前后值；BOXX、SGOV 和其他标的完全一致。
- 未启用 v4 时首页更多操作和录入选择层提供“启用双券商账本”；启用后改为“校准双券商组合”和“买入股票”。旧 `/positions/new` 与 `/cash` 直接访问时转入新路径。

### 5.5 数据安全与 JSON 备份恢复

- 顶部“更多操作”显示“数据安全与恢复”，进入独立页面；页面第一屏说明资产 current 保存在当前 ChatGPT 登录账号的 Sites D1，同一账号跨设备读取。浏览器持久存储状态只描述本机草稿与缓存，不能被写成账号备份状态。
- 页面显示“最近生成数据副本”和“最近成功恢复”时间。生成时间只表示 App 生成过文件，必须明确提示用户自行确认文件已保存到 App 外。
- 页面提供“导出数据副本”，并关联 JSON 文件包含当前股票数量、成本和 IBKR 现金记录的隐私说明。
- 点击后按钮显示“生成中…”，同一时刻只允许一次导出。
- 文件名包含导出 UTC 时间，扩展名为 `.json`。
- 支持文件分享时优先打开系统分享面板，用户可自行选择“存储到文件”或其他目标；文件分享不可用或非取消型失败时，回退为浏览器本地下载。
- 用户关闭分享面板时显示“已取消导出，当前持仓没有被修改”。生成或交付失败时显示“未能生成备份，当前持仓没有被修改，请重试”。
- 成功发起分享或下载后提示用户确认文件已经保存。产品不能仅因分享面板返回或下载被触发就宣称副本已经被用户永久保存。
- 旧 current 导出 JSON v2，v4 book 导出 JSON v3；两者都只包含当前活动 current。未保存表单、上一版本、行情/汇率缓存、legacy 数据和同步内部状态不进入文件。
- “从 JSON 恢复”接受本产品 v2 或 v3 文件；先在当前设备检查文件大小、受支持标的、歧义、现金 fallback 和严格格式，再显示导出时间、股票/输入数量、成本与双现金等预览。解析失败不得出现确认按钮，也不得写入账号。
- 恢复按钮只在账号股票、现金与 v4 book 全空、预览非空且用户完成第二次确认时可用。确认文案明确“只恢复 current、不合并、不覆盖；任何失败都不写入”。D1 CAS 开始后发现目标非空时显示拒绝原因，并保留全部账号数据。
- 恢复成功后提示资产数量以及“已写入当前登录账号，同账号其他设备可见”；任一失败提示“没有写入任何资产”。来源 revision 不继承；恢复从账号 revision 1 开始且没有 previous。恢复不包含草稿、行情/汇率缓存、legacy 或同步内部状态；原始文件不持久化，确认后只上传规范化 current。
- 文案统一称“JSON 数据副本”“空组合恢复”或“current-only 恢复”；不得称为自动备份、云备份、完整设备恢复或可合并恢复。

### 5.6 复制持仓资料到剪贴板或 ChatGPT

- 顶部“更多操作”使用贴底白色圆角面板；上方保留刷新行情、数据安全与恢复、导出数据副本，下方“持仓资料”分组并列“仅复制持仓资料”和浅蓝强调的“复制并打开 ChatGPT”。说明文案为“两种方式生成同一份 USD 资料；均不会自动发送”。空组合不显示两个复制入口。
- 点击任一入口后打开同一底部范围菜单。股票超过 5 只时显示“前 5 大持仓”，超过 10 只时再显示“前 10 大持仓”；始终提供全部范围，有现金时名为“全部资产”并包含 IBKR 现金；有股票时再提供“选择单只持仓”。选择具体范围或单只即执行当前目标，不增加预览或二次确认。
- 前 5/前 10 固定按未舍入市值降序，缺价标的置后并按代码稳定排序。单只选择列表沿用相同顺序。
- 股票操作菜单在“加仓”与“删除”之间依次显示“仅复制这只持仓资料”和“复制并打开 ChatGPT”；页面不增加逐行复制按钮。
- 范围菜单根据目标明确说明：普通复制“仅写入系统剪贴板，可粘贴到任意应用”；ChatGPT 路径“复制并预填为待发送 Prompt”。两条路径生成相同文本，均不调用 OpenAI API。
- 普通复制最终选择后只调用系统剪贴板并关闭范围菜单，页面显示 Toast“已复制，可粘贴到其他应用”，不得打开外部 URL。ChatGPT 最终选择先调用剪贴板，再打开 `https://chatgpt.com/?prompt=<编码后的同一文本>`；iOS 未接管时允许进入网页，页面不得声称一定打开 App。
- ChatGPT 中必须停在待发送输入框，不自动发送。PWA 不等待、读取或展示 ChatGPT 回答，也不要求 ChatGPT API key。
- 普通复制写入失败时显示“系统未能自动写入剪贴板”与同一只读文本；不得出现 ChatGPT 文案。ChatGPT 剪贴板写入失败不改变待发送文本，预填、长度或路由失败时仍可使用只读文本或剪贴板手工粘贴；不得误报已经发送。
- 手工回退、关闭、Escape、背景点击和用户返回 PWA 后都正确恢复焦点；生成或跳转期间禁用重复操作。
- 自动复制成功后显示紧凑浮层 Toast；普通复制为“已复制，可粘贴到其他应用”，ChatGPT 为“已复制并打开 ChatGPT”。Toast 不获取焦点、不推动页面内容，并在页面可见一小段时间后自动消失；页面处于后台时不消耗 ChatGPT 路径的展示时间，复制失败不显示成功 Toast。
- 文本首屏只显示范围、USD、分钟级生成时间，以及一条组合级 Alpaca 延迟/非实时、价格时间范围和最后有效价说明；现金单独存在时不显示无意义的股票行情说明。
- 组合只保留资产、股票数量与定价完整性、必要的股票市值/成本/浮动盈亏、现金/仓位和所选范围覆盖。定价完整时不列出 `100%` 覆盖或 `$0.00` 未定价成本，只有缺价才显示缺价成本与排除边界。
- 持仓明细使用一张表，表头只出现一次；列固定为排名、标的、数量、均价、现价、市值、盈亏、收益率和仓位。上一有效价以 `*` 标记，隔夜指示价以 `†` 标记，缺价写“暂无有效价格/无法计算”。
- 不复制逐股上市市场、币种、总成本、行情 provider/feed、市场时段、状态、价格类型、事件时间或获取时间；这些信息继续保留在数据层供估值和排障。
- 文本只陈述组合与持仓事实，不出现“请分析”、荐股或买卖动作；ChatGPT 只出现在交付入口和状态文案中，不写进 Prompt 正文。

### 5.7 USD / 人民币显示模式

- 总仓位标题区使用两个触控目标组成的分段切换：“USD”和“人民币”；当前项通过文字、底色和 `aria-pressed` 同时表达。
- 有有效汇率时，点击“人民币”即同步切换总览标题与金额、2 × 2 核心指标、股票行金额、现金余额与利息估算；利率和 NAV 的 USD 口径标记不换算。
- 今日变化金额与其他金额使用同一笔未舍入 USD/CNY 汇率折算；今日涨跌幅保持不变。汇率切换不得改变今日变化的 USD 真值或完整性状态。
- 人民币模式显示“人民币估算”、`CNY` 或 `¥`，并在持仓表下方披露“1 USD ≈ X CNY”及实际来源。Alpaca 结果写“Alpaca 中间价”和汇率时间；ECB 结果写“欧洲央行日参考汇率”、参考日与官方更新时间。使用缓存时写“上次有效汇率”或“上次有效参考汇率”。
- 披露同时说明：人民币仅供估算，录入和复制资料仍为 USD，不计算汇兑盈亏。
- 汇率加载期间可继续查看 USD；只有 Alpaca 与欧洲央行在线来源均失败，且从未取得合格缓存、缓存超过 7 天或结构无效时，才禁用“人民币”并显示紧凑提示“人民币估算汇率暂时不可用，当前继续显示 USD”。
- 用户已处于人民币模式时，暂时刷新失败可以继续使用 7 天内的上一有效值；超过有效期后自动回到 USD，不能显示 `¥0.00`。
- 模式仅改变显示，不修改持仓、排序、行情缓存、JSON 备份或复制文本。

### 5.8 组合分析与巴菲特框架顾问

- 首页在总览与持仓表之间显示两个并列按钮：“组合分析”和“巴菲特框架顾问”。按钮只显示名称，不附模型、上下文、功能说明或“打开”等辅助文案；入口不得放入视觉隐藏容器或只存在于“更多操作”。
- “组合分析”打开名为“组合分析”的独立、可关闭、可滚动 dialog。点按入口就是明确触发，挂载后立即显示简短“分析中…”状态并开始初始体检；不得在其中放置聊天输入、发送边界、隐私链接、同意按钮、示例、建议问题、固定快照说明、模型/时间元信息或重新体检。
- 组合分析成功态显示 AI 体检标题与摘要、行业暴露、工具角色、六个维度和可展开逐只分类。行业区必须标明“AI 推断”，占比由本机把分类映射回未舍入仓位后汇总；缺价不以成本补入。每个金额、比例、排名与覆盖数来自本机 evidence，随当前 USD/CNY 模式切换；模型正文不显示数字。
- 组合分析失败、超时、限流、未配置或不合规时只显示紧凑错误和“重试”，同时继续显示下方确定性结构与今日贡献；不得附加“持仓没有被修改”等重复说明。
- “巴菲特框架顾问”打开同名独立 dialog。标题下明示“方法论模拟 · 非本人或官方服务”；空消息区说明直接提问、会使用的价值投资视角、没有一手证据时的停止边界、发送的当前组合字段、排除的身份/存储字段和关闭清除。文本框占位为“直接问：这个判断的证据够吗？”，打开后聚焦；不显示同意按钮、示例问题、建议问题、字数计数或重启入口。
- 通过完整 contract 的 assistant 消息在正文下方显示一到三个中文 framework lens 标签，再显示本机 evidence 标签。用户消息不显示 lens；空、重复、未知或超数量 lens 的回答不部分展示。
- 打开对话、聚焦输入框、输入或修改草稿都不请求。点按发送或在非输入法组字状态按 Enter 才提交，Shift+Enter 换行；请求期间禁用重复提交并显示紧凑“正在回答”，但“完成”、Escape 与背景关闭始终可用，不能把手机用户困在等待状态。失败时保留原问题供重试。
- 对话首次发送固定当时组合快照，后续使用同一快照和最近六轮成功历史；父页自动行情刷新不替换已开始上下文。关闭 dialog 或刷新页面后清除消息与快照；重新打开后的下一次发送建立新会话。
- 结构区先显示定价覆盖状态和二维环形图；环心显示最大单股占比，下方按未舍入股票市值降序列出逐股占比、金额与现金，再显示 Top 1、股票合计、Top 3 和 Top 5。所有占比使用“已定价股票市值 + 现金本金”同一分母。
- 环图最多单独显示前 5 大股票；第 6 名起合并为“其他股票”扇区，逐股明细仍完整保留并使用同一“其他股票”颜色，禁止因小扇区过多造成虚假精度或隐藏持仓。
- 有缺价股票时，标题和说明明确写“部分口径”，列出未计价数量；缺价行占比显示“暂无”，不得使用剩余成本或 `0%`。没有可计价资产时整个结构占比不可用。
- 今日区只在全部股票都具备估值价与最近常规收盘价时显示组合今日净额；部分缺失时净额显示“暂无完整结果”，并显示“已计算 X/Y 只”。
- 绝对贡献按 `abs(单股今日变化) / Σ abs(可计算股票今日变化)` 排序，以零为中心的条形图保留金额正负与红涨绿跌；摘要同时显示组合净贡献和正向/负向绝对贡献比例。部分可计算时明确只代表可计算子集；绝对变化总量为零时显示“今日绝对贡献暂无”，不制造 `0%`。
- 现金行不进入今日贡献。人民币模式使用同一汇率折算结构详情中的金额，结构/贡献百分比和排序不变。
- 结构、集中度、贡献、金额、占比和覆盖状态始终由确定性公式完成；AI 只负责分类、选择证据和生成结构化短文/问答。详情不引入当前新闻、财报、宏观、基本面、历史收益、基准或 ETF 穿透数据源；无法计算的历史波动、Beta、相关性、因子暴露、估值、穿透和外部归因必须明示缺口。不提供目标价、收益保证、预测或直接交易指令，也不使用会降低数值可读性的 3D 球形图。

## 6. 行情状态

### 6.1 持仓行状态

持仓页面在列表层级只显示一次轻量说明：“15 分钟延迟”。该说明不暴露逐行 provider、feed、市场时段或日期时间，也不是独立行情汇总卡。

每只已定价持仓行只显示估值价，不显示：

- 市场时段；
- 市场事件日期或时间；
- 行情偏旧或过期；
- “上一有效价”；
- 隔夜或指示性成交提醒。

这些字段继续在数据层用于行情选择、新鲜度判断、缓存覆盖和故障排查。页面精简不得改写或删除 `provider`、`feed`、`priceType`、`sourceEventAt` 与 `fetchedAt`。

部分缺失时，总览标题使用“已定价市值”，缺价持仓行显示：

```text
暂无有效价格 · 未计入已定价市值
```

`[用户确认 2026-07-31]` 首页不显示独立行情汇总卡。页面级只披露一次约 15 分钟延迟；持仓行不显示市场时段、行情日期时间、偏旧、过期、上一有效价或隔夜提醒。请求故障可在总览下方显示紧凑错误提示，但不能恢复成行情汇总卡。

禁止使用“实时”“当前准确价”或“同步券商”。

### 6.2 状态行为

| 内部状态 | 首页文案 | 数字行为 |
|---|---|---|
| 盘前/常规盘/盘后健康延迟行情 | 无逐行状态 | 使用 `delayed_sip` 新价；延迟在页面级披露 |
| 隔夜健康延迟行情 | 无逐行状态 | 使用 `overnight` 指示性成交；延迟在页面级披露 |
| 行情老化或过期 | 无逐行提醒 | 按领域规则使用候选或上一有效价，保留原元数据 |
| 近期无成交 | 无逐行提醒 | 保留上一有效价与原元数据 |
| 异常候选价 | 请求故障时可显示紧凑提示 | 隔离新价，不覆盖上一有效价 |
| 从未取得价格 | “暂无有效价格” | 不以 `0` 参与组合估值 |
| 已收盘或休市 | 无逐行状态 | 使用最后有效价；没有最后价格时明确写“暂无有效价格” |

任一失败都不能把上一有效价格写成 `0`、空字符串或新的伪时间。

## 7. 加载、刷新与恢复

- 初次加载时使用骨架或明确的加载状态，不先显示完整的零值组合。
- 刷新期间保留当前可解释结果和原时间。
- 成功取得新数据后才能更新内部获取时间；首页不单独展示 App 获取时间卡。
- 单个标的失败不应清空其他标的。
- PWA 可见时每分钟刷新；从后台恢复时立即补刷。页面被 iOS 暂停或关闭时不承诺后台刷新。
- 汇率最多每 15 分钟主动刷新；一次服务端尝试内部先用 Alpaca，失败时自动用欧洲央行日参考价。从后台恢复时只有距上次尝试已满 15 分钟才补刷。两个来源失败都不改变股票行情刷新频率。
- 网络或保存错误使用面向用户的说明，不展示 provider secret、认证头或原始敏感响应。
- 页面刷新或另一设备登录后从账号 D1 活动 current 恢复，不能用展示缓存作为持仓真值。
- 页面刷新后独立读取股票快照和 IBKR 现金记录。现金记录缺失或无法读取不得清空或阻断已有股票显示；页面使用紧凑提示说明未清空数据。
- 某标的修改、加仓或删除失败时，其当前活动版本及其他标的保持可查看。
- 删除确认期间禁止重复提交；revision 冲突时提示持仓可能已在另一页面变化。
- 备份生成、用户取消、分享失败或下载失败都不清空、不覆盖也不创建任何持仓版本。
- 恢复解析和预览不写入；非空账号、二次确认取消、D1 CAS 竞争或任一写入失败时全部账号 current 都保持原状。恢复成功后从账号 repository 重新读取 current，行情与汇率按正常流程刷新，不从文件恢复缓存。
- 普通复制、ChatGPT 跳转、拒绝或手工回退都不清空、不覆盖、不创建持仓版本，也不向本产品服务端上传资料。普通复制没有外部导航；只有 ChatGPT 路径会把 Prompt 交给 `chatgpt.com`，不得把该路径描述成“完全不上传”。

账号登录、D1 current 与同账号跨设备读取进入 P0；离线新增、跨账号共享、旧 origin 自动迁移和自动版本化云备份不进入 P0，UI 不得提前承诺。

- 主屏幕模式正确使用名称、图标、启动路径和安全区域。
- 添加到主屏幕时，Safari 可从公开只读的固定 Vercel URL 取得 `apple-touch-icon`；该 URL 不显示页面、不接收账号资料，安装后的启动地址仍为 owner-only Sites。
- P0 不注册 Service Worker，也不承诺完整离线应用壳或离线编辑。
- 触控目标至少为 44 × 44 CSS px。
- 正文默认至少 16 CSS px。
- 支持动态字体，关键数字不能因放大而重叠。
- 文本和背景满足 WCAG 2.2 AA。
- 正负、错误和状态不能只靠颜色。
- 表单错误与字段关联，提交失败后焦点进入第一个错误。
- 尊重 `prefers-reduced-motion`，不依赖复杂动画。
- 在支持文件分享的 iPhone 环境中可以把 JSON 交给系统分享面板；不支持时仍能使用本地下载回退。两条路径都需要真机验证后才能声明通过。
- 文件选择、恢复预览、二次确认、成功与失败提示在 iPhone Safari 和主屏幕模式中可完成；大字号和 VoiceOver 能读出当前是否为空、将恢复什么以及失败零写入边界。
- 在 HTTPS 的 iPhone Safari 与主屏幕 Web App 中，最终复制选择由用户点击直接触发系统剪贴板和 ChatGPT HTTPS Prompt 跳转；真实设备需分别验证 App 接管、网页回落、Prompt 待发送、中文换行、长列表完整性和 App 未安装/未登录状态。失败时手工复制/粘贴路径仍可用。
- 在 320–430 CSS px、200% 文字和 VoiceOver 下，USD / 人民币分段切换、汇率说明和人民币金额不得重叠、裁切或引发页面横向滚动。
- 在同一移动端范围下，现金行、现金表单、利率预览和二次删除确认不得重叠、遮挡键盘主路径或依赖颜色表达含义。
- 在同一移动端范围下，“今日盈亏”指标格的金额主值、涨跌幅副值和辅助描述不得重叠、裁切或引发横向滚动。
- 在同一移动端范围下，组合结构与今日贡献详情的部分口径、覆盖数量、正负金额和绝对贡献百分比不得裁切或只靠颜色表达；打开和关闭后焦点位置可预测。
- 在同一移动端范围下，趋势图不裁切总资产或 2 × 2 指标；指针探查不阻断纵向滚动，键盘与 VoiceOver 可读出同一真实点。减少动效时不得依赖动画理解数值。
- 在 320–430 CSS px 与 200% 文字下，五列表头、简称和逐股今日涨幅不得重叠；仅持仓表内部允许预期横向滚动，页面主体不得横向漂移。名称/代码列固定，任意行起手可移动整表，横滑后页面仍可上下滚动。

## 9. 内容术语

统一使用：

- “总仓位”或“组合总览”；
- “合并持仓”；
- “估值价”，不写“实时价”；
- “约 15 分钟延迟”只在持仓页面级披露一次，不在每只健康持仓行重复；
- “行情时间”表示市场事件时间，仅在数据层与诊断证据中使用；
- “获取时间”表示 App 获得数据的内部时间戳，仅在数据层与诊断证据中使用；
- “上一有效价”和“指示性成交”保留为内部行情语义，不在首页持仓行展示；
- “估值不完整”表示部分持仓没有有效价格。
- “JSON 数据副本”或“手动导出副本”表示用户主动保存的 current-only v2/v3 文件；“空账号恢复”表示当前设备完成严格预览后，只将规范化 current 写入完全空的登录账号；不使用“自动备份”“云备份”“完整设备恢复”或“合并恢复”。
- “仅复制持仓资料”表示写入系统剪贴板并留在 PWA；“复制并打开 ChatGPT”表示复制同一文本并进入待发送 Prompt。两者都不使用“AI 诊断”“一键发送”或暗示已经提交的文案。
- “人民币估算”表示用一笔近期有效 USD/CNY 汇率派生金额；Alpaca 结果可写“中间价”，欧洲央行结果只能写“日参考汇率”。不得写成“人民币成本”“实时汇率”或“汇兑盈亏”。
- “上次有效汇率”表示刷新失败后仍在 7 天有效期内的缓存值，必须同时显示其真实来源时间。
- “IBKR 现金”表示用户在本机手动记录的 USD 现金资产，不表示 App 已连接或同步 IBKR。
- “今日盈亏”表示按当前股数相对最近常规收盘价计算的全股票仓价格影响估算；可见范围必须同时保留“估算”，不得写成“已实现盈亏”或“实时盈亏”。
- “组合结构”表示已定价股票市值与现金本金在同一分母下的占比；缺价时必须带“部分口径”。“绝对贡献”表示单股今日变化绝对值占可计算股票绝对变化总量，不等于带方向的净盈亏占比。
- “组合分析”表示基于当前完整 current-only 快照的 AI 体检与确定性结构/贡献；“巴菲特框架顾问”表示用户发送后才开始的有限多轮问答。“AI 推断”不等于 MSCI 官方证券分类或实时主数据；不得称为“智能荐股”“涨跌预测”或“风险评级”。“今日驱动”只指谁贡献了今日已计算变化，不等于股票涨跌的外部原因。
- “今日走势”表示真实 SIP 15 分钟收盘点按当前股数派生的当日价格影响与估算资产；不使用“账户回报曲线”“历史收益”或“实时走势”。
- “官网公布档位年利率”、“NAV 调整后档位年利率”和“整笔现金混合年利率”是三个不同口径，不得互相替换；利息统一使用“估算”。

成本表单明确提供“平均成本”和“剩余总成本”两种模式；首页统一使用“总剩余成本”和“合并平均成本”表示派生结果。

## 10. UI 完成边界

当前 UI 已串联 Sites D1 账号 repository 与固定 Vercel provider 安全边界；现有浏览器证据覆盖空首页、320/375/390/430 px 紧凑持仓布局、模拟 200% 根字号、多组十进制预览、草稿刷新恢复和安全 provider 故障。只有以下完整路径在目标 iPhone 通过后，才可声明 PWA UI 已完成首版设备验收：

1. 空组合进入当前持仓快照；
2. 保存包含一项有效输入的标的批次；
3. 从普通录入入口再次保存同一标的，保存前看到当前值、本次输入和叠加后的合并结果；
4. 返回首页后同一标的仍只有一条，数量、总成本和均价按全部有效输入重算；
5. 首页第一屏读取总仓位；
6. 点按或静止长按持仓打开同一操作菜单，分别验证修改回填、加仓叠加、单只复制只读和删除二次确认；从股票行横滑后即使浏览器补发点击也不得打开菜单；
7. 修改、加仓或删除失败时原持仓保持不变；
8. 查看页面级单次延迟披露、缺价与请求故障；确认首页不显示逐行市场时段、日期时间、过期、上一有效价或隔夜提醒，也没有独立行情汇总卡；
9. 从“数据安全与恢复”导出 current-only JSON v2/v3，确认系统分享或本地下载可用、文件可读且导出前后账号 current 不变；
10. 在完全空账号中选择有效 v2/v3 文件，核对预览并二次确认，通过 D1 CAS 恢复规范化 current；再验证非空目标、无效文件、取消、并发和失败路径都零写入，草稿与行情/汇率缓存不从文件恢复；
11. 从首页分别打开“组合分析”和“巴菲特框架顾问”：验证两个独立 dialog；组合分析点按即加载并覆盖成功/失败、行业/角色本机暴露、逐只推断、六维体检、确定性结构/贡献和 CNY；巴菲特框架顾问打开零请求，空态覆盖非冒充、方法论和运行时数据边界，发送后覆盖完整上下文、framework lenses、本机证据、连续追问/最近六轮、固定快照、换行、失败保留草稿、关闭清除、200% 文字、VoiceOver 与减少动效；
12. 从“更多操作”的两个目标分别复制全部、前 5/前 10，并从股票菜单验证两个单只入口；确认范围文本一致，普通复制留在 PWA，ChatGPT Prompt 保持待发送，目标专属 Toast、手工回退与复制前后持仓不变；
13. 在真实 iPhone Safari 和主屏幕模式分别验证 ChatGPT App 接管与网页回落，确认短文本、中文、换行和长列表完整；模拟未安装、未登录、预填失败或超长文本时，确认剪贴板/只读文本仍可手工粘贴，且完整 URL 不进入本站日志或测试证据；
