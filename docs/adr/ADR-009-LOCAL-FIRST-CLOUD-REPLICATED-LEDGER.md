# ADR-009：本地优先、云端复制

## Status

Superseded by ADR-012

## Context

旧文档曾把“iPhone 本地完整副本 + 私有云同步”记录为已确认决定，并据此设计 outbox、游标和冲突处理。

最新产品基线把产品收敛为无券商维度的统一持仓查看器。产品所有者随后确认 P0 使用 IndexedDB 本地保存，不提供登录、云同步或跨设备。

## 历史提案

本 ADR 曾建议在确认需要本地与云端双重保存后：

- 本地按用户命名空间保存完整数据副本；
- 本地写入与待同步 outbox 原子提交；
- 云端按稳定 ID 和幂等键接收记录；
- 同一经济输入在两端只生效一次；
- 冲突保留并要求显式处理，不按最后写入静默覆盖；
- 退出登录时清理设备上的可读私人副本；
- 提供独立导出作为恢复路径。

最终数据结构必须服从 ADR-010。组合计算键为：

```text
instrument
```

若以后需要登录，用户标识只用于数据隔离，不改变组合内的计算键。不得重新引入券商实体或券商分组。

## 被取代原因

`[用户确认 2026-07-30]` P0 使用 IndexedDB 保存当前持仓快照，无登录、云同步或跨设备。P0 的绑定决定见 ADR-012；若以后扩大为云同步，需要重新确认产品范围并新增 ADR。

## Consequences

- 双重保存提高恢复能力，但显著增加认证、同步、冲突、隐私与部署复杂度；
- 仅本地最简单，但需要清晰的导出和设备丢失风险提示；
- 本 ADR 已被取代，也不授权创建云资源、账号或部署。
