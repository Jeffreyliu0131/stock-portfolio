# ADR-029：持仓表固定名称列并整块横向滑动

## Status

Accepted

**Date:** 2026-08-03

**Decider:** 产品所有者

## Context

五列持仓信息在 iPhone 宽度内继续压缩会降低数字可读性，并使较长金额、第五列今日涨幅与小字金额互相挤占空间。产品所有者要求参考 MooMoo 持仓表的浏览方式：名称/代码保持在左侧，其余数据通过左右滑动查看；手势从持仓区下方任意一行开始时，也必须带动同一张表。

现有股票行仍承担长按操作，页面也需要继续上下滚动，因此横向浏览不能制造独立行滚动、误触长按或锁死纵向页面手势。

## Decision

- “名称/代码”作为固定身份列；“市值/数量”“估值价/均价”“盈亏/收益率”“今日涨幅”作为可横向浏览的数据列。
- 表头、全部股票行和 IBKR USD 现金行放在同一个横向滚动容器中，共享唯一的横向滚动位置；禁止每行各自滚动。
- 横向手势可以从表头或任意股票/现金行开始。名称/代码列在整个过程中保持固定，数据列从其下方滑过。
- 持仓表使用稳定的最小内容宽度，不再为了塞进 320–430 CSS px 强行压缩五列，也不在极窄容器或文字放大时改成两列卡片。横向滚动只发生在持仓表内部，不得造成整个页面横向漂移。
- 同一触摸区域同时允许横向持仓浏览和纵向页面滚动。指针移动超过既有阈值时取消待触发的股票长按，避免横滑打开操作菜单；静止长按和键盘打开操作继续有效。
- 滚动区域提供可读名称和说明，并可聚焦；方向键、Home 和 End 支持键盘横向浏览。
- 保留当前浅色账户页设计、红涨绿跌、字段内容、计算、IndexedDB、行情、复制和持仓操作。参考只用于表格结构与交互，不引入 MooMoo 商标、图标、行情入口或交易功能。

## Consequences

### Positive

- iPhone 上每列获得稳定宽度，金额和百分比无需继续缩小即可完整核对。
- 用户在长列表下方起手也能移动整张表；表头与每一行始终对齐。
- 固定代码与简称为横向浏览提供持续身份锚点。

### Trade-offs

- 后侧列不再保证首屏全部可见，需要通过露出的下一列和“左右滑动”提示建立可发现性。
- 固定列需要与普通行、按压态和现金空状态保持相同背景，否则滚动内容会从固定列下方透出。
- 真实 iPhone Safari、主屏幕模式、VoiceOver 和文字放大仍需设备验收。

## Amends

- 修订 ADR-020 的连续表格布局：五列字段与视觉层级保留，移动端改为固定身份列加共享横向滚动。
- 修订 ADR-028 的宽度策略：取消“320–430 CSS px 强行容纳五列”和“极窄时两列重排”，字段、简称与逐股今日涨幅/金额决定继续有效。

## Verification

发布前必须证明：

- 320、390、430 CSS px 下持仓表 `scrollWidth > clientWidth`，页面本身没有非预期横向滚动；
- 从表头、首行、下方股票行和现金行横滑时，整表使用同一 `scrollLeft`，名称/代码列与表头身份列位置不变；
- 横滑到终点后第五列百分比和小字金额完整可见，第四列累计盈亏保持原语义；
- 横滑后仍能上下滚动页面，横向移动不会误触长按，静止长按、现金点按和底部主操作继续可用；
- 键盘与辅助技术能识别横向浏览区域及其说明；
- 完整自动化门禁通过，真实 iPhone Safari、主屏幕模式和 VoiceOver 另行验收。
