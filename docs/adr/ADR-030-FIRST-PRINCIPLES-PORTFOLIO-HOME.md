# ADR-030：用第一性原理收敛持仓首页

## Status

Accepted

**Date:** 2026-08-08

**Decider:** 产品所有者

## Context

首页的核心任务是让用户立即回答三个问题：总资产是多少、赚亏如何、各资产如何构成。原账户身份区、资产/持仓/现金导航和证券类别标签没有对应的多账户、分页或筛选功能，会在核心数字之前增加没有决策价值的层级。3 × 2 指标矩阵同时展示成本、盈亏、收益率、项目数和币种，将核心数据与可由其他控件表达的状态放在同一层。

产品所有者确认继续保留固定名称列与五列整表横滑，因为用户需要查看完整持仓信息；同时确认删除无功能的外壳，并把股票与现金统一收入底部“录入资产”入口。

## Decision

- 顶部只保留“总仓位”、USD / 人民币显示切换和“更多操作”；删除账户身份区、资产/持仓/现金导航和无实际筛选功能的资产类别标签。
- “更多操作”收纳刷新行情、导出数据副本和复制持仓资料；这些次级操作不与总资产或录入主路径竞争。
- 总资产继续是唯一一级数字。次级指标固定为 2 × 2：累计浮动盈亏/持仓收益率、今日盈亏/组合涨跌幅、股票剩余成本、现金本金。股票成本直接使用既有未舍入 `portfolioOpenCost`，不把现金混入。
- 页面级行情延迟和定价状态紧跟总资产区，且延迟只披露一次。汇率和现金利息详细边界保留在页尾。
- 五列持仓表、固定名称/代码列和整表共享横向滚动继续有效。现金行在每个数据单元内明示“现金余额、NAV 调整利率、估算年利息、今日变化”，不让股票表头改写现金语义。
- 普通点按股票行打开与长按相同的操作菜单；长按作为快捷方式保留。横向位移超过阈值时同时取消待触发长按并抑制随后的点击，避免横滑误打开菜单。
- 底部固定区只有一个“录入资产”主按钮；点按后选择“录入股票”或“录入 IBKR 现金”。空组合使用同一入口，不再同屏放两个竞争按钮。
- 本决定只修改信息架构、交互可发现性和视觉层级；持仓聚合、估值、汇率、现金利息、IndexedDB、导出和复制的业务语义不变。

## Consequences

### Positive

- 用户打开首页后先看到总资产和两种盈亏口径，不再先穿过无功能的账户外壳。
- 四个次级指标各自回答一个资产决策问题，币种和项目数由已有控件和列表表达。
- 点按路径提高持仓操作可发现性，同时保留高密度横滑表的完整信息。

### Trade-offs

- 刷新、导出和复制多一次打开“更多操作”；这是用一次额外点按换取更清晰的首页主任务。
- 现金行为表达自身语义会比股票行稍高；五列对齐和共享滚动保持不变。
- 真实 iPhone Safari、主屏幕模式、VoiceOver 和动态字号仍需设备验收。

## Amends

- 修订 ADR-020 的账户身份/导航/证券分区、3 × 2 指标矩阵和底部摘要布局；浅色分区、深色总资产质感、红涨绿跌和五列字段继续有效。
- 扩展 ADR-017：股票行点按成为标准入口，长按作为快捷入口保留。
- 补充 ADR-023 的现金行展示语义，不改变现金公式或存储。
- 保留 ADR-029 的整表横滑，并将横向位移后的点击抑制纳入误触验收。

## Verification

- 320、390 和 430 CSS px 下顶部控件、2 × 2 指标和底部主按钮不裁切，页面主体无非预期横向滚动。
- 首页不再出现账户身份区、页面导航或无功能资产标签；行情延迟只显示一次。
- 普通点按和静止长按打开同一股票操作菜单；横滑后即使浏览器补发 `click` 也不打开。
- “录入资产”只出现一个底部主按钮，选择后分别进入现有股票或现金表单。
- USD / 人民币、部分缺价、纯现金、未录入现金、导出、复制、删除与错误恢复的自动化门禁通过。

`[实现事实 2026-08-08]` 上述界面与交互已经实现。36 个测试文件中的 308 项测试、TypeScript、领域构建和 Next.js 生产构建通过；320/390 px 浏览器检查覆盖空状态、现金、CNY、更多操作、统一录入和横滑终点。React StrictMode 初始加载竞态在压力测试中暴露后已修复并加入回归测试。真实 iPhone、200% 文字、VoiceOver 和含有效行情股票页面仍待设备验收；代码尚未提交或发布。
