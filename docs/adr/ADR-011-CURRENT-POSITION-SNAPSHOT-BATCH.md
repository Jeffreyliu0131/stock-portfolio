# ADR-011：P0 使用当前持仓快照批次

## Status

Accepted

Amended by ADR-044：本 ADR 继续约束未启用 v4 的旧 current；用户确认双券商校准后，活动组合由独立 v4 book 投影，旧 v3 current 原样保留。

保存意图由 ADR-015 修订：普通录入已有标的时叠加新输入；从首页进入完整编辑时才整批替换。本文其余当前快照、原子版本切换、恢复和非交易语义继续有效。

用户可见编辑与恢复交互由 ADR-017 进一步修订：“修改持仓”回填合并数量与均价，首页不再提供历史恢复入口；存储层保留版本只作为故障防护实现资产。

**Date:** 2026-07-30
**Decider:** 产品所有者

## Context

统一组合需要确定用户如何维护持仓。逐笔交易账本会立即引入 BUY、SELL、卖出成本、已实现盈亏和交易更正等尚未需要的语义；P0 的目标是让用户录入当前持仓并查看可信的统一估值。

同一标的可能来自多处，用户仍需要分别录入各组数量和成本，以便系统先合计数量与成本，再计算合并均价。不同标的各自维护独立批次。

## Decision

P0 采用“当前持仓快照批次”：

- 一个快照批次描述保存时一个标的的全部当前输入；
- 同一标的允许存在多组数量与成本输入；
- 成本录入支持“平均成本”或“剩余总成本”两种成本模式；
- 保存操作以该标的新的完整批次替换其当前活动版本，不把表单行解释为追加交易，也不修改其他标的；
- 保存必须原子完成；失败时该标的当前活动版本与其他标的保持不变；
- 成功替换后必须保留该标的上一成功版本的恢复或撤销路径；
- 组合计算仍按 `instrument` 汇总，公式只引用 `02-DOMAIN-AND-CALCULATIONS.md`。

P0 不记录 BUY、SELL、成交价、交易时间线、已实现盈亏或税务批次。以后若加入逐笔交易，必须新增产品决定、迁移方案和 ADR，不能把快照行直接解释为历史交易。

## Consequences

### Positive

- 用户可以按标的直接录入来自多处的当前数量和成本；
- P0 不依赖尚未确认的卖出成本公式；
- 全批替换避免重复保存造成持仓被意外累加；
- 版本化快照为覆盖、更正和恢复提供明确边界。

### Negative

- 产品不能回答历史买卖、已实现盈亏或某日持仓；
- 编辑时需要展示该标的整个当前批次，避免用户误以为单行保存是追加；
- 本地存储需要按标的原子切换活动版本并保留可恢复版本。

## Supersedes

本 ADR 与 ADR-010 一起取代 ADR-002 的逐笔账本产品方向。ADR-007 中的 SELL 规则不进入 P0。
