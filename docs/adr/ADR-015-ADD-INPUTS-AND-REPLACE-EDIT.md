# ADR-015：普通录入叠加，完整编辑替换

## Status

Accepted

Amended by ADR-044：旧 current 路径继续使用本文语义；v4 双券商账本启用后，普通资产变化改由带券商与现金联动的 BUY/SELL 写入，修正使用重复校准。

首页编辑入口由 ADR-017 修订为“修改持仓”：回填当前合并数量与均价，并以单项当前快照替换旧批次；“加仓”继续使用本文的叠加语义。

**Date:** 2026-07-30
**Decider:** 产品所有者

## Context

ADR-011 确认 P0 使用按标的维护的当前持仓快照批次，但把所有保存都定义为整批替换。实际主路径中，用户从统一录入入口再次输入同一股票的不同数量和成本时，预期系统直接叠加这些分项并计算合并数量、总成本和均价。整批替换会覆盖前一次输入，要求先载入旧批次也会打断本次录入。

产品需要区分两个用户意图：

- 再次录入一组当前持仓分项；
- 完整修正某标的现有全部分项。

## Decision

### 普通录入

- 普通录入入口用于增加当前持仓分项。
- 若标的尚不存在，本次输入形成首个活动批次。
- 若标的已经存在，下一完整批次由当前活动批次的全部原始输入与本次新输入共同组成。
- 保存前必须显示当前持仓、本次输入和保存后的合并数量、总成本与均价。
- 保存后首页仍只显示一条该标的合并持仓。

### 完整编辑

- 用户从首页持仓行进入“编辑完整持仓”。
- 页面载入该标的当前批次的全部原始输入。
- 保存时，编辑页提交的完整集合替换当前批次；用户删除的旧输入不再保留。

### 共同边界

- 叠加与替换都在单个 IndexedDB 事务中创建下一完整版本并切换活动快照。
- 两种操作都保留上一成功版本，失败时当前版本与其他标的不变。
- 同一提交在进行中不得重复计入。
- 普通录入的叠加只表示新增一组当前持仓分项，不产生 BUY、SELL、成交时间、已实现盈亏或交易流水。
- 聚合公式继续只引用 `02-DOMAIN-AND-CALCULATIONS.md`：先求数量与成本总和，再由总成本除以总数量。

## Consequences

### Positive

- 用户可以分多次录入同一股票，不需要自己重填或计算旧数据。
- 新增分项与修正整批数据有不同入口和明确文案。
- 首页、领域聚合和 IndexedDB 活动快照保持同一标的一条结果。

### Negative

- 普通录入与完整编辑需要两种保存命令和对应测试。
- 普通录入不是交易记录，界面必须持续避免“买入”或交易时间线文案。

## Amends

本 ADR 修订 ADR-011 中“所有保存均整批替换”的部分。ADR-011 的当前快照批次、原子版本切换、上一版本恢复以及不记录逐笔交易等决定继续有效。
