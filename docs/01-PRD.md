# iPhone 美股统一持仓 PWA PRD

## 1. 用户确认基线

以下内容来自产品所有者 2026-07-30 至 2026-08-23 的明确表达，是当前首版产品真源：

- `[用户确认 2026-07-30；2026-08-20 修订]` 产品不允许用户自由创建、重命名或管理券商账号；启用 v4 后，校准和交易固定选择 IBKR 或 moomoo 以维护底层来源持仓与现金，首页仍按标的合并。
- `[用户确认 2026-07-30]` 用户通过一个统一入口录入持仓数据。
- `[用户确认 2026-07-30]` 来自两处的同一标的数据只用于数学合并，不形成两个需要管理的产品对象。
- `[用户确认 2026-07-30]` 相同标的必须合并显示。
- `[用户确认 2026-07-30]` 首页核心任务是让用户直观看到合并后的总仓位。
- `[用户确认 2026-07-31]` 首页不能继续沿用原有页面骨架；整页排版和视觉按 Futu 账户页的丰富程度重新设计。
- `[用户确认 2026-08-08]` 首页使用浅色分区与深色总资产质感，但删除无功能的账户身份、资产/持仓/现金导航和资产类别标签。顶部只保留总仓位、币种切换和更多操作；总资产下使用 2 × 2 核心指标；底部只保留一个“录入资产”按钮，再选择股票或 IBKR 现金。五列整表横滑完整保留。
- `[用户确认 2026-08-09]` 首页按 Robinhood 高级资产页进一步升级：总资产、当日变化、真实当日线和 2 × 2 指标组成连续纯黑英雄区，已确认的浅色持仓表、红涨绿跌、币种切换与操作语义保留。
- `[用户确认 2026-08-09；2026-08-12 修订]` 首页趋势只保留一条由 Alpaca Historical Bars SIP 15 分钟收盘点和当前持仓数量估算的“今日走势”；不显示 `1W / 1M / 3M / 1Y / ALL`、历史菜单入口或历史导入页。缺少真值时不画假线。
- `[用户确认 2026-08-23]` 首页进一步降噪：有股票时的页面级行情说明只显示“15 分钟延迟”；趋势图下方不再重复“今日走势 · 按当前股数估算 · 现金不参与”。底层行情与趋势计算、2 × 2 今日盈亏的“估算”边界、缺价和请求故障表达不变。
- `[用户确认 2026-08-12；取代 2026-08-11 决定]` 控制器不再读取历史账本或自动记录 NAV；`/history` 重定向首页。既有本机历史记录不删除，但不展示、不继续累积。停用的解析和计算模块不能在没有新确认时重新进入运行路径。
- `[用户确认 2026-08-11；2026-08-12、2026-08-15、2026-08-20 修订]` 固定个人 Production 启动载荷和自动恢复路径退出产品。全新 Sites 账号保持空组合，只能由用户手工录入或使用 FR-12 的 JSON v2/v3 空账号恢复。移除运行路径不删除、迁移或改写旧 Vercel origin 中的 current、独立历史数据库或旧完成标记。
- `[用户确认 2026-07-30]` 涨幅、正收益和正盈亏使用红色；跌幅、负收益和负盈亏使用绿色。符号与文字继续表达正负，颜色不是唯一线索。
- `[用户确认 2026-07-30]` 产品形态是 iPhone 优先的 PWA。
- `[用户确认 2026-07-30]` MVP 股票行情使用 Alpaca `delayed_sip`。
- `[用户确认 2026-07-30]` 估值跟随盘前、常规盘、盘后和 24/5 隔夜市场；用户接受约 15 分钟延迟，隔夜使用 Alpaca `overnight` 指示性成交，休市显示最后有效价。
- `[用户确认 2026-07-30；2026-08-12、2026-08-20 修订]` 未启用双券商账本时，旧 current 继续按标的维护快照批次。用户确认校准后，v4 按 IBKR/moomoo 子持仓与手工 BUY/SELL 驱动 current 投影；这不重新启用长期历史收益或文件导入。
- `[用户确认 2026-08-22]` BOXX、SGOV 与所有其他受支持股票使用同一买卖现金规则。用户只看到一个组合现金池：任意卖出净额进入现金，任意买入成交额与手续费从现金扣减；券商只用于确认股票来源数量和剩余成本，不要求另选现金账户。
- `[用户确认 2026-08-20]` 首页仍按标的合并展示，但校准与每笔买卖必须选择 IBKR 或 moomoo。买卖同时更新该券商数量、剩余成本和已结算/待结算 USD；另一券商不变。旧 v3 current 不自动迁移、删除或改写。
- `[用户确认 2026-07-30]` 同一标的可包含多组数量与成本输入；成本录入同时支持平均成本和剩余总成本两种模式。
- `[用户确认 2026-07-30]` 从普通录入入口再次录入已有标的时，新输入叠加到其当前批次，并直接重算合并数量、总成本和均价。
- `[用户确认 2026-07-30 至 2026-08-12；2026-08-20 修订]` 未启用 v4 时，点按或长按持仓仍打开“修改持仓、加仓、仅复制这只持仓资料、复制并打开 ChatGPT、删除持仓”；确认 v4 校准后，写操作改为买入、卖出和校准，两个复制入口保留，首页仍不展开券商股票拆分。
- `[用户确认 2026-07-31]` 组合总览与持仓列表之间不显示独立行情汇总卡；约 15 分钟延迟在页面级只披露一次。首页持仓行不显示市场时段、行情日期时间、偏旧、过期、上一有效价或隔夜提醒；缺价仍明确标记，请求故障可使用紧凑的页面级提示。
- `[用户确认 2026-07-30]` P0 支持 Alpaca 可解析的 USD 美国上市股票与 ETF，不支持 OTC、期权、加密货币或非美国市场；美国存托凭证（ADR）若能作为受支持的美国上市股票解析，则可以使用。
- `[用户确认 2026-07-30]` 录入时用户只输入股票代码；停止输入后自动由 Alpaca 识别名称和上市市场，不再要求点击验证或手动选择市场。币种固定为 USD，不显示币种选项。
- `[用户确认 2026-07-30；2026-08-20 修订]` IndexedDB 本地原型成为旧 Vercel 来源；Sites Production 使用 ChatGPT 登录与 D1 账号 current，同一账号跨设备读取同一组合。IndexedDB 只保留设备草稿与可替换缓存。
- `[用户确认 2026-07-30]` 首页需要把当前手机中已保存的持仓手动导出为 JSON；导出和后续修改不得弄丢现有数据。
- `[用户确认 2026-08-09；2026-08-20 修订]` JSON v2/v3 可在当前设备严格校验和预览后恢复到完全空的账号组合；不合并、不覆盖，空目标复查与 current 写入通过同一个 D1 compare-and-swap 更新完成，任何失败零写入。源 revision 只校验；恢复为账号 revision 1 current，不恢复草稿、行情/汇率缓存、legacy 或同步内部状态。
- `[用户确认 2026-08-09]` 首页提供组合结构与今日贡献详情。结构分母为已定价股票市值加现金本金，缺价股票不以成本或 `0` 代替并标为部分口径；组合今日净额只在全部股票可计算时显示，绝对贡献占比按单股今日变化绝对值占可计算股票绝对变化总量计算，缺失不补 `0`。
- `[用户确认 2026-08-13；2026-08-15、2026-08-28 修订]` 首页提供“组合分析”和“巴菲特框架顾问”两个独立入口与弹层。点按组合分析直接触发 DeepSeek V4 Flash 六维体检与逐只行业/角色推断；巴菲特框架顾问是非冒充的公开价值投资原则模拟，打开零请求且可直接输入，首次发送才建立 current-only USD 完整固定快照，后续附最近有限轮对话。空态紧凑披露方法边界及会发送/不会发送的字段，不设同意页。每个回答必须返回可验 framework lenses，一手基本面不足时输出证据缺口。请求仍排除身份、账号、设备、存储内部、历史库与备份；确定性公式、本机 Decimal 数字、安全输出和无持久化边界继续是真源。
- `[用户确认 2026-08-17；2026-08-20 修订]` ADR-043 的字节、字段、限流、固定上游、响应头、无敏感日志和 provider 预算原则继续约束 Vercel provider。Sites 页面改为 owner-only 登录；五个 provider API 只允许精确 Sites origin 的无 credentials CORS，这一跨域限制不代替身份认证。
- `[用户确认 2026-08-17；2026-08-20 修订]` ADR-043 的请求/上游/日志安全原则继续有效；“Production 公开且不登录”被 ADR-045 取代。Sites Production 必须 owner-only ChatGPT 登录。
- `[用户确认 2026-08-01；2026-08-09、2026-08-12 修订]` 首页为前 5、前 10、全部或单只聚合持仓资料提供“仅复制持仓资料”和“复制并打开 ChatGPT”两个入口。两条路径复用同一份 USD 事实文本、范围、未舍入市值排序和单只组合上下文；普通复制写入系统剪贴板并留在 PWA，ChatGPT 路径复制后通过 `https://chatgpt.com/?prompt=` 预填待发送 Prompt。
- `[用户确认 2026-08-09；2026-08-12 修订]` ChatGPT App 未接管 HTTPS 链接时允许回落网页；系统剪贴板和手工复制/粘贴继续作为回退。普通复制不得构造或打开 ChatGPT URL。两条路径均不自动发送、不调用 OpenAI API，不把回答带回 PWA；文本只含事实数据，不附带预设提问、分享面板、截图或图片。
- `[用户确认 2026-08-09；2026-08-12 修订]` 成功反馈使用目标明确的短暂 Toast：普通复制显示“已复制，可粘贴到其他应用”，ChatGPT 路径显示“已复制并打开 ChatGPT”。不得把成功文案作为持续内容插入总览与持仓列表之间；失败状态使用目标对应的手工回退。
- `[用户确认 2026-08-03]` 复制资料用于粘贴给用户自行选择的 AI 获取建议。输出改为组合摘要与紧凑持仓表，只保留会改变判断的资产规模、定价完整性、股票成本与盈亏、现金与仓位、范围覆盖及持仓核心数据；逐股行情排障元数据压缩为全局延迟/价格时间范围和必要例外标记。
- `[用户确认 2026-08-02]` 首页提供 USD / 人民币显示模式切换；人民币金额从未舍入 USD 真值派生，只作估算，不建立第二套成本或汇兑盈亏。汇率优先使用 Alpaca 最新 `USDCNY` 中间价；Alpaca 未配置或不可用时使用欧洲央行每日参考交叉汇率，两个来源均不可用时继续显示 USD。
- `[用户确认 2026-08-03；2026-08-08 修订]` 首页不设置独立今日入口或持仓表模式切换。2 × 2 核心指标固定为累计浮动盈亏/持仓收益率、今日盈亏/组合涨跌幅、股票剩余成本和现金本金。今日口径、五列持仓表、现金排除和缺值完整性规则不变。

## 2. 问题与目标

### 2.1 问题

用户的美股持仓数据分散在两处。分别查看时，很难快速知道：

- 同一股票合计持有多少；
- 合并后的成本和估值是多少；
- 整个组合当前大概处于什么仓位；
- 哪些股票或现金构成了主要资产暴露，哪些股票推动了当天波动；
- 估值价格来自什么时候，是否仍可参考。
- 手机本地数据丢失后，怎样从自己保存的副本安全恢复而不误改已有组合。

### 2.2 首版目标

1. 在一个统一入口录入当前持仓数据，无需任何券商设置。
2. 按规范化标的合并数量和成本，避免同一股票分成多行。
3. 旧 current 保留普通录入、加仓和修改；确认双券商校准后，股票菜单改为买入、卖出和校准。券商只选择股票来源，所有股票买卖都与统一组合现金原子联动。
4. 在首页第一屏以总资产、2 × 2 核心指标和固定名称列、可横向浏览的五列连续持仓表展示总仓位、累计/今日表现与资产构成。
5. 全天跟随美股实际市场时段估值：盘前、常规盘和盘后使用 `delayed_sip`，隔夜使用 `overnight`；首页页面级只披露一次约 15 分钟延迟。
6. 行情异常、陈旧或不可用时在数据层诚实降级，不用 `0` 或伪造的新时间污染结果；首页只呈现缺价和必要的请求故障。
7. 在 iPhone Safari 和主屏幕 PWA 形态下完成查看与录入主路径。
8. 用户可以把当前已保存持仓手动导出为本地 JSON 副本，在后续修改或浏览器数据丢失前自行保存一份可读数据。
9. 用户先选择“仅复制”或“复制并打开 ChatGPT”，再完成任一范围或单只选择。两个目标得到同一份低噪音资料；普通复制留在 PWA，可粘贴到其他应用，ChatGPT 路径进入待发送 Prompt 并可回落网页。两者均不改变持仓、不调用 OpenAI API，也不自动发送。
10. 用户可以一键把首页总览和持仓行切换为人民币估算，同时保留 USD 真值和原收益率。
11. 用户可以录入 IBKR USD 现金，在同一资产列表和总资产中看到现金本金，并理解当前公开规则下的利率和利息估算。
12. 用户打开首页即可在 2 × 2 核心指标中看到整个股票组合的今日盈亏估算金额及组合涨跌幅，无需进入独立入口或切换持仓表。
13. 用户可以从数据安全页检查持久存储状态、导出 current-only JSON v2，并只在完全空组合中经过严格预览和二次确认原子恢复股票与现金。
14. 用户可以查看组合结构、Top 1/3/5 集中度、现金占比和今日绝对贡献，在缺价或缺少前收时清楚知道结果覆盖范围。
15. 用户打开首页即在连续纯黑英雄区看到总资产、今日收益和唯一一条真实 SIP 15 分钟“今日走势”；没有周期选择器或历史入口，不可用时明确说明原因，不生成假收益。
16. 用户可分别点按“组合分析”阅读六维体检与行业/资产角色暴露，或打开独立“巴菲特框架顾问”直接提问并连续交流；打开对话不发送，发送后固定首次快照。数字与权重继续由本机真值渲染，AI 不可用时确定性详情仍完整可用。

### 2.3 非目标

- 不为股票持仓创建、选择、重命名、删除或展示券商；不创建 IBKR 账户管理体系。
- 不连接券商账户，不收集券商凭证，不同步券商数据，不执行交易。
- 不提供荐股、下单、税务或投资建议。
- 不自动发送 ChatGPT Prompt，不在 PWA 内调用 OpenAI API，也不读取、保存或展示 ChatGPT 回答。
- DeepSeek 组合咨询当前不连接新闻、财报、宏观、基本面、历史收益、基准或 ETF 底层持仓数据源；不把模型记忆伪装成当前真值，不输出目标价、收益保证、价格预测、荐股或直接买卖/加减仓指令。
- 不把延迟行情描述成实时行情。
- 不提供长期账户收益、历史导入、历史事件记录或税务口径已实现盈亏；停用的历史代码不进入运行路径。
- 不提供跨账号共享、无人值守迁移、完整离线编辑或自动交易。
- 不支持向已有账号组合合并或覆盖、定时版本化云备份或自动读取旧 origin IndexedDB。
- 不保留固定个人资产载荷、Production 自动恢复或其他无人值守恢复例外。
- current 持仓录入不支持 OTC、期权、加密货币或非美国市场；历史期权只通过独立事件和券商 NAV 进入组合收益。
- 不生成长期账户收益，也不显示长期周期占位或不可用按钮。

## 4. 核心用户流程

1. 用户打开 Sites PWA；未登录时先完成 ChatGPT 登录，只有通过 owner-only 访问后进入组合。
2. 没有数据时，首页直接提供“录入资产”入口，再选择股票或 IBKR 现金。
3. 用户输入股票代码，页面自动通过 Alpaca 识别名称和上市市场，并在统一表单中填写该标的一组或多组数量与成本；币种固定为 USD。
4. 若该标的已存在，普通录入页自动把当前批次纳入“保存后合并预览”，直接显示现有输入与本次输入合计后的数量、总成本和均价。
5. 未启用双券商账本时保留旧普通录入；用户从更多操作进入校准并确认两边当前值后，首页切换为买入、卖出、校准和复制。买卖时选择股票所在的 IBKR/moomoo、数量、成交均价、手续费和现金状态，保存前同时预览该券商股数与统一组合现金前后值。
6. 用户返回首页，直接看到 USD 口径的组合总仓位和合并持仓列表。
7. 用户可点击列表中的 IBKR 现金项，录入现金余额、Pro/Lite 和可选账户 NAV；保存后现金本金计入总资产，列表显示 NAV 调整利率、整笔混合利率和估算年利息。
8. 用户可点击“人民币”切换整个首页的金额显示；系统按同一笔有效 USD/CNY 汇率折算，优先使用 Alpaca 中间价，必要时使用明确标注的欧洲央行日参考汇率；股数与收益率保持不变。
9. 首页总资产指标矩阵直接显示全股票仓今日盈亏估算金额和组合涨跌幅；持仓表第四列继续固定显示累计浮动盈亏与持仓收益率，第五列显示逐股今日涨幅，并在下方用小字显示逐股今日盈亏金额。
10. 同一英雄区只显示真实“今日”持仓估算线；线上可探查真实时点和派生金额，暂无数据时保留解释状态而非伪造曲线。
11. 用户从“更多操作”进入“数据安全与恢复”，核对账号 current 并导出 JSON v2/v3；选择恢复文件后先在当前设备严格校验和预览，只有账号全部 current 为空且二次确认后才原子写入 D1。
12. 用户从首页点按“组合分析”，在独立详情中查看 DeepSeek 六维体检、行业/资产角色暴露、集中度、现金占比、逐股结构和今日贡献；失败时确定性结构与贡献仍可读。用户也可点按旁边的“巴菲特框架顾问”，在方法论/隐私空态下直接输入；输入期间零请求，首次发送建立固定快照，后续对话延续上下文；回答显示 framework lenses 和本机证据，关闭或刷新后清除。
13. 用户从“更多操作”先选择“仅复制持仓资料”或“复制并打开 ChatGPT”，再选择前 5、前 10、全部或单只；股票菜单也提供两个单只目标。最终选择只生成一份文本：普通复制写入剪贴板并留在 PWA；ChatGPT 路径写入剪贴板并打开 `https://chatgpt.com/?prompt=<编码后的同一文本>`。失败时使用同一文本手工复制/粘贴。
14. 系统按当前市场时段取得 Alpaca 延迟股票行情并更新估值，同时在数据层保留市场时段、feed、行情时间和获取时间；首页页面级只披露一次约 15 分钟延迟；前台每分钟刷新，从后台恢复时补刷。
15. 股票行情失败或过期时，系统继续安全使用上一有效价；首页不显示逐行过期或时间提醒，请求故障使用紧凑提示，已有有效价格不得被 `0` 覆盖。
16. 汇率最多每 15 分钟刷新；Alpaca 未配置或失败时自动请求欧洲央行日参考价，两个在线来源失败时可使用 7 天内的上一有效汇率并披露真实来源元数据，无可用值时人民币模式不可用且首页继续显示 USD。

该流程不包含券商创建、券商选择、券商拆分或券商管理页面。IBKR 现金是一条固定 provider 的本机资产记录，不连接或同步券商账户。

## 5. 功能需求

### FR-01：统一持仓录入

- 用户无需完成券商设置即可开始录入。
- 表单不得要求券商名称、券商选择或券商账号。
- 输入必须包含 Alpaca 可解析的受支持标的、有效数量和成本。
- 用户停止输入有效代码约 0.5 秒后，页面自动发起标的识别，不要求点击额外验证按钮。
- 上市市场由 Alpaca 返回结果匹配并只读展示，不要求用户搜索或选择。
- 币种固定为 USD，不显示币种选择器。
- 同一标的允许存在多组输入。
- 成本录入支持“平均成本”和“剩余总成本”两种模式；系统按领域公式把每组输入换算为剩余成本真值。
- 无效十进制数、非正数量和不支持的标的必须在保存前得到可理解的错误提示。
- 保存失败不得清空用户已填写内容。
- 普通录入遇到已有标的时，必须把本次有效输入叠加到当前批次；不得覆盖或丢弃原输入。
- 从首页长按进入“修改持仓”时，表单回填当前合并数量与合并均价；保存语义是用这一组值替换该标的当前批次。
- 从首页长按进入“加仓”时，只适用于未启用 v4 的旧 current；v4 启用后直接转入 BUY。
- 旧叠加和替换不表示交易历史；v4 BUY/SELL 使用独立严格事件和 revision，不允许重复 event id。

### FR-02：统一组合计算

- 相同规范标的的有效输入只显示为一条合并持仓。
- 合并数量、剩余成本和平均成本的规范公式以 `02-DOMAIN-AND-CALCULATIONS.md` 为准。
- 不得把多个平均成本直接做算术平均。
- 所有计算使用未舍入真值；展示舍入值不得写回计算输入。
- 不同规范标的不得误合并。
- OTC、期权、加密货币、非美国市场及 Alpaca 无法解析的标的不得进入 P0 快照。

### FR-03：首页总仓位

- 首页第一屏必须直接显示组合总览。
- 首页必须展示按标的合并持仓和 IBKR USD 现金项的连续资产列表。
- `[用户确认 2026-07-31；2026-08-03 修订]` 合并持仓使用“名称/代码、市值/数量、估值价/均价、盈亏/收益率、今日涨幅”五列连续表格，不把每个标的呈现为大块卡片；名称左对齐，数值右对齐。
- 持仓表第四列固定显示领域已定义的累计浮动盈亏与持仓收益率；第五列主值显示逐股今日涨幅，下方小字显示逐股今日盈亏金额，不提供模式切换，行内不重复“估算”文案。
- 股票行名称删除 `.com`、`Inc.`、`Corp.`、`ETF` 等常见展示后缀并减少左右留白；完整名称仍用于股票身份、复制资料和辅助技术。
- `[用户确认 2026-07-31]` 资产总览固定显示估算总市值、总剩余成本、浮动盈亏和持仓收益率；总市值是唯一一级数字。
- `[用户确认 2026-08-08]` 存在现金记录时，一级数字为股票已定价市值加现金本金的总资产。2 × 2 次级指标分别显示股票浮动盈亏/收益率、股票今日盈亏/涨跌幅、股票剩余成本和现金本金；未入账利息不计入任何一格。
- 当部分持仓没有有效价格时，总览必须使用“已定价市值”等部分口径，缺价持仓行必须明确说明未计入；首页不需要再显示 `4/4` 一类数字覆盖卡。
- 股票持仓不得展示券商名称、券商数量或券商管理入口。现金行可显示固定 provider `IBKR`，不提供账户选择或券商管理。
- 首页总资产指标矩阵显示“今日盈亏”：主值显示整个股票组合的今日盈亏金额，副值显示组合涨跌幅并标注“估算”。组合中任一股票缺少有效估值价或最近常规收盘价时两者都显示不可用，不得把缺失项按 `0` 生成完整结果；现金本金、NAV 和利息估算都不参与。
- 首页不显示独立行情汇总卡；约 15 分钟延迟在页面级只披露一次。持仓行不显示市场时段、行情日期时间、偏旧、过期、上一有效价或隔夜提醒；缺价仍明确显示。
- 点按或长按持仓打开同一修改、加仓、复制和删除菜单，并提供键盘或辅助技术的等价入口；横滑后不得触发菜单。

### FR-04：行情与状态

- 股票行情 provider 固定使用 Alpaca，并通过服务端 adapter 获取：盘前、常规盘和盘后使用 `delayed_sip`，20:00–04:00 ET 的有效隔夜时段使用 `overnight`。
- `overnight` 价格在领域层保留 `INDICATIVE_TRADE` 类型；若标的暂时没有新的隔夜成交，则回退到最近的 `delayed_sip` 或上一有效价，不显示 `0`。
- 周末、节假日或休市时在数据层保留最后有效价和原事件时间，不把旧价伪装成仍在变化。
- 客户端不得接触 provider 密钥。
- 每条行情必须保留 `provider`、`feed`、`priceType`、`sourceEventAt` 和 `fetchedAt`。
- 能安全识别前一常规收盘价时，行情 contract 同时保留 `previousRegularClose`；无法可靠识别时保持缺失，禁止猜测或以 `0` 代替。
- 页面必须在页面级明确写出一次“15 分钟延迟”或等价说明，不得在每只健康持仓行重复，禁止使用“实时”。
- App 在前台每分钟刷新，从后台恢复时补刷，不承诺被 iOS 暂停或关闭后的后台刷新；市场时段继续参与行情选择，但首页不逐行显示。
- 抓取成功不等于价格健康；状态还必须考虑事件时间和市场状态。
- `[用户确认 2026-07-31]` 首页不显示独立行情汇总卡，也不逐行显示市场时段、行情日期时间、偏旧、过期、上一有效价或隔夜提醒。页面级只披露一次约 15 分钟延迟；请求故障可使用紧凑的全局错误提示。
- 隔夜行情回退到 `delayed_sip` 或上一有效价时继续在数据层保留真实状态、价格类型与原行情时间，首页不增加逐行隔夜提醒。
- 新行情异常、过期或请求失败时，在数据层保留上一笔有效价和原时间；首页只在请求故障时显示紧凑提示。
- 从未取得有效价格时显示未知，不得以 `0` 参与总仓位估值。
- 当日趋势使用独立 Historical Bars 边界：服务端固定 `feed=sip`、`timeframe=15Min`、`adjustment=split`、`currency=USD`，查询结束时间不晚于服务端当前时间减 15 分钟。
- Historical Bars 路由只接收标的和可选 `asOf`，不接收股数、成本或现金。按当前数量的组合估算在浏览器内完成，不写入 IndexedDB。

### FR-04A：Robinhood-inspired 组合趋势

- 总资产、当日估算变化、趋势图、“今日”标记与 2 × 2 核心指标在同一连续纯黑英雄区内；不使用纹理、假卡片或品牌复制弱化总资产层级。
- 每个趋势点使用当前未舍入股数、该时点最后已知收盘价和最近常规收盘价；现金本金加入该点估算总资产，不加入今日价格影响或涨跌幅分母。
- 只提供“今日走势”这一种范围，不显示周期选择器；不得把当前数量回套长期价格或显示长期占位。
- 缺最近常规收盘价、缺/失败 series、点数不足、纯现金或请求失败时显示可理解的暂无走势状态，不用 `0`、直线或插值生成假曲线。
- 实际隔夜点未接入时不展示；以后接入时只作为具有真实时间和全标的覆盖的独立点，不与 SIP 历史插值连线。
- USD 是趋势计算真值；CNY 仅按当前有效汇率派生每点展示金额，不改变百分比或写回任何真值。

### FR-04B：停用的历史能力边界

`[用户确认 2026-08-12]` 本节能力已经退出 P0 和产品运行路径。首页没有入口，`/history` 重定向首页，控制器不得查询历史库、自动记录 NAV 或展示长期收益。下列条目只保留为既有本机数据和停用代码的安全边界，不能作为重新启用授权：

- 历史中心支持直接粘贴文字、一次选择多份 IBKR/moomoo CSV/文本层 PDF/文本文件，以及打开一次性本机预览链接；所有入口复用同一严格解析与预览，确认后才写入独立历史 IndexedDB。
- 一次性链接只在 URL fragment 中携带最小化的月结单文字，进入页面后立即从地址栏清除，不触发服务端请求、日志或持久化；不能绕过阻断诊断和确认按钮。
- 原始文件、提取文本、姓名和完整账户号不持久化或发送服务端；保存文件 SHA-256、不可逆来源范围、规范化 NAV/现金流/交易事件和诊断。
- 外部入金/出金进入 Modified Dietz；买卖、内部转账、换汇、股息、利息、税费和佣金保留在表现中。未知分类阻断相关区间的完整收益。
- 历史期权与股票分别建模；交易汇总行和执行明细不得重复。只有交易没有 NAV 时不生成长期线。
- 当前持仓摘要只能证明当前估值与 `1D`，不能被当作历史 NAV；识别到这类文本时必须给出具体阻断原因。
- 历史页提供未来 BUY、SELL、DEPOSIT、WITHDRAWAL 手工记录；这些事件不自动改写 current 持仓。

### FR-04C：Production 启动不自动写入个人资产

- 客户端源码和构建产物不得包含固定个人股票数量、成本、现金或可用于恢复这些值的载荷。
- Production 首页启动只读取当前登录账号 D1 current。positions、cash 与 broker 同时为空时，显示真实空组合，不调用恢复、不创建资产、不写入一次性完成标记。
- 已有来源中的股票 current、现金 current、previous、草稿、行情/汇率缓存、独立历史库和旧完成标记均保留原样；移除启动路径不执行清理或 schema 迁移。
- 用户要把旧 Vercel current 带入 Sites 时，先在旧 origin 导出 JSON v2/v3，再在空账号中使用 FR-12 的严格预览、二次确认和 D1 原子恢复；禁止自动迁移。

### FR-05：PWA UI

- UI 必须覆盖空组合、统一录入、合并结果、加载、部分缺失、陈旧行情和请求失败状态。
- 主路径以 iPhone Safari 为基准，并适配安全区域和主屏幕独立模式。
- owner-only Sites 的 iPhone 安装不得依赖匿名请求会被 `401` 阻断的同源图标；HTML 与 manifest 必须引用可匿名读取、无用户数据的版本化 Vercel PNG，并保持 Sites `start_url`、scope 和 identity 不变。
- 涨幅、正收益和正盈亏使用红色；跌幅、负收益和负盈亏使用绿色。
- 金额、数量、正负和状态不能只靠颜色区分。
- UI 实现完成前，不得把产品描述为“可直接使用”。

### FR-06：账号 current、修改与删除

- Sites 使用 D1 按稳定登录用户 ID 保存 current；邮箱与姓名不得作为资产键或持久字段。
- 旧股票/现金 current 与 v4 book 继续使用独立严格 contract，但在同一账号 state 中持久化；D1 `state_version` 与领域 revision 同时保护并发。
- 每个标的的新版本完整写入后才能切换为活动版本；任一写入失败时该标的旧活动版本不变。
- 成功替换后可在存储层保留上一成功版本作为故障防护，但首页和普通用户路径不提供历史恢复入口。
- 删除必须在第二次明确确认后执行，并原子删除所选标的的账号 current/previous；本机草稿只作辅助清理，其他标的不受影响。
- 删除现金记录同样需要第二次确认，且只改变账号现金 current，任何股票快照不受影响。
- 刷新、重新打开或另一设备登录后，系统从账号活动 current 重算组合，不把展示缓存当作持仓真值。
- Sites P0 必须登录并把 current 写入账号 D1；设备草稿与行情/汇率缓存仍保留在本机。自动版本化云备份不进入 P0。

### FR-07：Sites Web runtime

- 页面使用 App Router、React 和 TypeScript；Sites 通过 Vinext、Vite、Sites plugin 和 Cloudflare Worker-compatible ESM 构建。
- Sites 独占 UI、登录和 D1 current。Alpaca/DeepSeek 密钥与 adapter 保留在 Vercel server-only 边界；Sites 不配置第二份 provider secret。
- 标的解析、行情、日内条形、USD/CNY 和 AI 的浏览器 client 只在精确 Sites Production origin 下改用固定 Vercel origin；其他 origin 仍使用同源相对路径。跨域请求不发 cookie 或 Authorization。
- P0 提供 manifest、standalone 主屏幕体验、ChatGPT 登录守卫和 D1 `DB` 绑定。
- PWA 图标是跨运行时的静态例外：`apple-touch-icon` 和 manifest icon 使用固定 Vercel HTTPS URL；Sites `img-src` 只允许该既有 origin，Vercel 图标响应允许匿名跨源读取且不接收 credentials。五个 `/api/*` provider contract 不因此扩大。
- Service Worker、完整离线应用壳和离线编辑不进入 P0。

### FR-08：手动 JSON 导出副本

- 首页提供可访问名称为“导出 JSON 备份”的手动操作。
- 导出只读取 `PositionRepository.listSnapshots()` 返回的当前活动 `PositionSnapshot` 和 `CashRepository.getCashSnapshot()` 返回的当前现金记录，不读取或输出上一版本、表单草稿、上一有效行情缓存、legacy 券商备份、outbox 或同步游标。
- JSON v2 顶层固定包含 `format`、`formatVersion`、`exportedAt`、`snapshots` 和 `cash`；每个股票快照保留 `revision`、`savedAt`、标的、可选名称及全部原始输入，`cash` 为当前现金快照或 `null`。
- 数量、成本和其他十进制真值继续使用 JSON 字符串，不能转成 JSON number 或展示舍入值。
- 导出从已认证账号 current 生成纯客户端文件，不新增备份上传接口，也不改变 D1 state 或本机 schema。
- 浏览器支持文件分享时优先调用 Web Share；不支持或文件分享失败时回退为本地 Blob 下载。用户取消分享或生成失败时，已保存持仓保持不变。
- 导出文件是用户自行保存的手动副本，包含私人持仓数量、成本和 IBKR 现金余额/NAV。只有 FR-12 定义的空组合 current-only 恢复可以读取该文件；生成时间不能证明用户已在 App 外保存，界面不得描述为自动或云备份。

### FR-09：复制持仓资料到剪贴板或 ChatGPT Prompt

- 首页“更多操作”在“持仓资料”分组下提供可访问名称分别为“仅复制持仓资料”和“复制并打开 ChatGPT”的两个操作；空组合不显示这两个操作。
- 复制范围为按未舍入股票市值降序的前 5、前 10、全部和单只；缺价标的置后并按规范代码稳定排序，与全部范围重复的前 5/前 10 不显示。存在现金时，“全部”包含 IBKR 现金和利息估算依据；前 5/前 10 仍只选股票。
- 股票操作菜单提供“仅复制这只持仓资料”和“复制并打开 ChatGPT”；两者的单只文本都包含组合摘要、该标的核心聚合结果、占已计价总资产比例与股票市值排名。
- 文本顶部包含 USD 口径、UTC 分钟级生成时间，以及一条 Alpaca 延迟、非实时、组合价格时间范围和最后有效价边界说明。
- 组合摘要只包含估算/已计价资产、股票总数与已定价数量、必要的股票市值、成本和浮动盈亏、现金余额与仓位，以及前 5/前 10 范围的市值和资产占比。定价完整时不重复输出覆盖率与零值拆分，存在缺价时才输出缺价成本和排除边界。
- 每只持仓在紧凑表中包含市值排名、代码与名称、数量、均价、估值价、市值、浮动盈亏、收益率和仓位；不重复输出上市市场、币种、总成本或逐股 provider、feed、时段、状态与时间。上一有效价和隔夜指示价只在现价上使用例外标记。
- 缺价必须写为“暂无有效价格/无法计算”，不得以 `0` 计算市值、盈亏、权重或排名。所有比例先使用未舍入领域真值计算，再做展示舍入。
- 文本只陈述数据，不附加 AI 提问、买卖建议或投资结论；不调用分享面板，不生成截图或图片。
- 用户完成任一目标下的前 5、前 10、全部或单只选择后，系统必须使用当前内存中的页面股票、行情和现金数据生成唯一文本；两个目标复用同一生成器与范围 contract，不在点击后重新读取 IndexedDB。
- 普通复制只把该文本写入系统剪贴板并留在当前 PWA，不得构造 ChatGPT URL、触发外部导航或打开分享面板。ChatGPT 交付使用 `https://chatgpt.com/?prompt=<百分号编码后的同一文本>`；iOS 接管时打开 App，未接管时允许进入网页，两者都停在待发送状态。
- 剪贴板写入不可用或被拒绝时，两条路径都保留相同内容的只读文本框和手工复制；ChatGPT 未预填、长文本被截断或路由失败时，用户还能粘贴该文本。
- 该流程不得调用 OpenAI API、自动发送 Prompt、轮询 ChatGPT 回答或把回答带回 PWA；不增加 ChatGPT access token、API key、账号连接或本产品服务端代理。
- 自动复制成功后只显示不占页面布局、自动消失的目标专属 Toast；不得写入页面级 `notice`。Toast 不获取焦点，辅助技术通过礼貌状态播报获知结果。剪贴板失败进入与目标相符的手工复制弹层。
- 复制、跳转、失败和手工回退都不得修改 D1 账号 current、本机草稿/缓存、提升 schema 或泄露内部字段。复制文本不上传本产品或 Vercel 服务端；普通复制没有外部 URL，只有 ChatGPT 路径会把 Prompt 交给 `chatgpt.com`，完整 URL 不得进入本产品日志、分析事件、缓存或错误回报。

### FR-10：USD / 人民币估算模式

- 首页总仓位标题区提供 USD / 人民币分段切换，默认显示 USD；切换同步作用于组合总览、资产指标和每只持仓金额。
- 人民币模式折算总资产、股票成本与现金本金、浮动盈亏、现金利息估算、组合今日变化金额、单只市值、估值价、均价和单只浮动盈亏；数量与利率/收益率、组合今日涨跌幅不变。
- 所有人民币金额由未舍入 USD 真值乘以同一笔有效 USD/CNY 汇率后再展示舍入；不得由已经格式化的美元数字二次换算。Alpaca 成功时使用 `MIDPOINT`；否则使用同一参考日 ECB CNY/EUR 除以 USD/EUR 得到的 `REFERENCE`。
- 汇率必须包含方向、provider、rate type、来源时间和抓取时间；ECB 结果还包含参考日。页面写明人民币为估算、显示实际来源与来源时间；ECB 必须标为日参考汇率，缓存值必须标为上一有效汇率。
- 汇率最多每 15 分钟主动刷新。7 天内上一有效值可用于降级；从未取得、超过 7 天或结构无效时禁用人民币模式并继续显示 USD，禁止回退为 `0`。
- 人民币切换、汇率缓存和折算结果不修改 D1 账号 current 或旧 Vercel IndexedDB 持仓。录入编辑、JSON 副本和复制资料继续使用 USD 真值；不计算汇兑盈亏。
- Alpaca 凭据只存在于服务端；ECB 降级请求不使用密钥。两个汇率来源失败都不得阻塞股票行情、录入、复制、备份或 USD 展示。

### FR-11：IBKR USD 现金与利息估算

- 首页列表始终提供 IBKR 现金入口；没有记录时显示“填写金额”，有记录时点按进入修改。空组合同时提供股票和现金两个录入入口。
- 现金表单必填大于 `0` 的 USD 余额，必选 IBKR Pro 或 IBKR Lite，可选大于 `0` 的 IBKR 账户 NAV。金额最多 8 位小数，真值不使用二进制浮点。
- NAV 必须是 IBKR 账户级数值，不得自动把本 App 的跨来源股票总资产冒充为 IBKR NAV。用户留空时必须保存 `navSource=CASH_BALANCE_FALLBACK` 且 `netAssetValue=balance`，并在表单、首页和复制文本中明确披露；来源为 fallback 但两值不相等时拒绝。
- `[外部事实 2026-08-02]` IBKR 直接客户 USD 正结算现金的公开档位为 Pro `3.13%`、Lite `2.13%`；首 USD 10,000 不计息，NAV 低于 USD 100,000 时档位利率按 NAV 比例降低。页面必须显示官方来源和 `2026-08-02` 核验日，不声称利率固定不变。
- 页面分开显示官网公布档位年利率、NAV 调整后档位年利率、整笔现金混合年利率、估算年利息和估算月均利息；不得把任一个口径写成保证收益。
- 现金本金直接计入当前总资产；估算利息没有入账事实，因此不累加到总资产、现金余额、浮动盈亏或持仓收益率。
- 保存失败时保留用户输入和已有记录；二次确认删除只作用于现金记录。现金读取异常不得阻断已有股票持仓的读取。

### FR-12：JSON v2 / 双券商 v3 空组合安全恢复

- 数据安全页接受旧 current `formatVersion=2` 或 ADR-044 双券商 `formatVersion=3`，先按顶层 format 路由各自严格解析器。v2 继续校验标的唯一性、十进制、时间、revision 与现金 fallback；v3 严格校验 book、来源持仓、两条现金与事件，不接受未知嵌套字段。
- 严格校验成功后展示导出时间、股票/输入数量、股票数量与剩余成本、现金余额和 NAV 等恢复预览；用户第二次明确确认前不得写入。
- 恢复目标必须同时满足账号股票、现金与 v4 book 全空；任一已有 current 时拒绝整次恢复，不提供合并、覆盖或按标的选择。
- 空目标复查与全部 current 写入必须位于同一个 D1 state compare-and-swap；校验、竞争或任一写入失败时最终写入为零，并发恢复最多一个成功。
- 源 revision 只验证合法性，不继承为账号版本；恢复后的 current 固定 `revision=1`、`nextRevision=2`、`previous=null`。不恢复草稿、行情/汇率缓存、legacy 备份、outbox 或同步状态；原始文件不持久化，确认后仅上传规范化 current。
- 空备份不执行恢复。最近生成副本时间与最近成功恢复时间只作当前设备提示；账号 current 本身可跨设备读取，但生成时间仍不能证明文件已保存到 App 外。
- v3 同样只创建 revision 1 / previous null 的 v4 current，源 revision 不继承且事件保留。

### FR-13：组合结构与今日绝对贡献

- 结构分母固定为已定价股票未舍入市值之和加现金本金；单股、现金及 Top 1/3/5 集中度使用同一分母。
- 缺价股票不以剩余成本、零或展示舍入值代替市值，不进入结构分母且占比不可用；存在缺价时明确标记部分口径和未计价数量。
- 单股今日变化金额沿用领域公式。组合今日净额只有所有股票均可计算时才显示；任何缺失不以 `0` 补齐，现金完全排除。
- 今日绝对变化分母为可计算股票单股今日变化金额绝对值之和；单股绝对贡献占比为其绝对值除以该分母。部分可计算时只能表述为可计算子集；分母为 `0` 时贡献占比不可用。
- 详情分别呈现最大正贡献、最大负贡献和绝对贡献排序。人民币模式只折算金额，占比与排序保持 USD 真值下的结果。
- `[用户确认 2026-08-09]` 详情使用二维环形图呈现仓位结构、使用以零为中心的正负条形图呈现今日贡献，并在同屏保留逐股金额、占比、覆盖范围与 Top 1/3/5。分析只解释当前确定性数据，不引入 3D 球形图或依赖 AI 生成投资结论。

### FR-14：完整上下文 AI 组合咨询与行业暴露

- 首页显示两个并列的低噪音按钮：“组合分析”和“巴菲特框架顾问”。两者分别使用独立 dialog，不在同一弹层混排。顾问空态显示非本人/非官方方法论模拟、会发送/不会发送的运行时字段和关闭清除；不显示同意按钮、示例问题、建议问题、字数计数或重新体检。
- 点按“组合分析”就是初始体检的明确触发动作；详情挂载后直接请求 AI，同时持续显示下方确定性结构与今日贡献。AI 失败只显示紧凑错误和重试。
- 打开“巴菲特框架顾问”、输入或修改草稿不发起请求。用户点按“发送”或在非组字状态按 Enter 才调用；Shift+Enter 换行。首次发送使用当时的 current-only USD 完整快照，后续只提交同一固定快照、最近六轮成功对话和新问题；关闭或刷新后清除。
- 浏览器从同一份当前 `PortfolioCopySource` 与 `PortfolioInsights` 生成 schema v4 快照。Sites 通过固定 Vercel provider route 调用 `deepseek-v4-flash`；API key 不进入浏览器、Sites、D1、仓库、日志或文档。
- 初始响应必须为每只持仓返回一条 `AI_INFERRED` 分类：资产角色、GICS 对齐行业、主题、置信度和依据。界面必须显示“AI 推断”；行业与资产角色占比由浏览器把已校验分类映射回当前 `assetWeight`，使用未舍入 Decimal 真值汇总；现金单独呈现，缺价继续是部分口径。
- 初始组合体检固定覆盖六个维度：资产与现金配置、单一/头部集中度、行业与主题暴露、持仓工具与潜在重叠、累计/今日贡献、数据边界。每项必须引用当前快照内可验证的 evidence ref，金额、比例、排名和覆盖数由界面使用当前 USD/CNY 模式重新渲染。
- 独立顾问使用 schema v4 `CHAT` 模式，不依赖初始体检或行业分类；其响应固定为空分类、空 brief、非空 answer、一到三个 framework lenses 和空建议问题，只允许引用基础组合与逐只持仓 evidence。旧 `FOLLOW_UP` contract 保留兼容，但当前 UI 不从组合分析发起。
- 当前快照不支持历史波动率、Beta、相关性矩阵、正式因子暴露、估值、基本面、ETF 底层穿透、基准或新闻归因。模型必须标明这些项目当前不可计算，不得使用训练记忆伪造实时或机构级结果。
- 模型正文不承载数字。未知/跨类证据、未知持仓、重复或变更分类、额外字段、数字、伪造高级指标、当前外部归因、目标价、收益保证、预测、荐股、买卖或直接加减仓措辞均整份拒绝，不展示部分结果。对交易动作问题只能转化为条件、权衡和待验证信息。
- 请求最多包含一百只持仓、十二条历史消息，并使用请求/响应大小限制、尽力限流、`no-store` 和服务端 kill switch。初始体检使用二十五秒总超时；CHAT 使用较小输出上限和十八秒总超时。语义十进制校验允许预期范围内的高精度派生比例。
- 请求、分类和对话只保存在当前 dialog 的 React 内存，不写 IndexedDB、`localStorage`、缓存、导出、复制资料、日志或分析事件。组合分析使用打开时快照；聊天使用首次发送时快照，父页自动刷新不替换已开始上下文；关闭后重新打开才建立新会话。
- 未配置、超时、限流、provider 故障或输出不合格时显示可重试的安全错误；确定性结构与今日贡献继续可用，持仓、现金、行情与汇率零改动。

### FR-15：双券商 current 校准、买入与卖出

- 首页统一股票身份不变；v4 内部固定以 `broker + instrument` 维护 IBKR/moomoo 子持仓。校准、买入和卖出是唯一可写入口，不增加自由账户管理。
- 首次校准读取旧聚合 current 只作对照，不猜测来源。用户逐股填写两边当前数量与剩余总成本，并填写两边已结算/待结算 USD；预览后二次确认，写入独立 v4 book。旧 v3 current、previous、草稿与缓存不改写。
- BUY/SELL 表单必须选择股票来源券商、数量、成交均价、手续费与 `PENDING | SETTLED`，保存前展示该券商股数和组合现金前后值；不再选择或展示独立券商现金池。
- BOXX、SGOV 与所有受支持股票使用同一公式。BUY 增加所选券商数量，剩余成本增加成交总额与手续费，组合现金减少同额。SELL 不得超过所选券商数量，剩余成本按该券商卖出前平均成本等比例减少，组合现金增加成交总额减手续费。
- 全卖只删除所选券商子持仓；若另一券商仍持有，首页合并行继续存在。负现金保留为融资负债；当前不估算融资利息。
- 任一领域校验、event id 重复、revision 冲突或持久化失败都必须使整个 v4 current 写入取消，股票、两边现金和事件均保持原值。
- 重复校准是处理遗漏交易、现金转账、入出金、股息、利息和券商成本差异的恢复路径；不生成长期收益或税务已实现盈亏。
- v4 current 使用 JSON v3 导出与空目标恢复。恢复前 `position_batches_v2`、`cash_accounts_v3`、`broker_portfolio_v4` 必须全部为空；恢复记录从 revision 1 开始且 `previous=null`。

## 6. 用户故事

### US-01：统一录入

作为用户，我希望无需配置券商就能直接录入持仓，以便尽快得到组合结果。

### US-02：同标的合并

作为用户，我希望来自两处的同一股票自动合并，以便不用自己再次计算。

### US-03：直观看总仓位

作为用户，我希望打开首页就看到统一组合总览和合并持仓，以便快速形成资产感觉。

### US-04：理解行情状态

作为用户，我希望页面只用一条延迟说明和必要的缺价或请求故障提示表达估值边界，不让每只持仓的日期时间与行情老化标签干扰资产判断。

### US-05：安全叠加与修正当前持仓

作为用户，我希望再次录入已有股票时直接看到叠加结果，也能在首页长按选择修改、加仓、复制单只资料或删除，以便用当前数量与均价快速修正、录入本次增加的数量与买入均价，或只读带走该股资料。

### US-06：手动保存当前持仓副本

作为用户，我希望从当前手机把已保存持仓导出成 JSON 文件，以便在继续修改前把当前数据另外保存一份，同时不让导出动作改变现有持仓。

### US-07：查看人民币估算

作为用户，我希望按一下按钮就把当前美股持仓切换成人民币估算，以便快速形成以人民币衡量的资产感觉，同时知道汇率来源时间且不改变原始 USD 数据。

### US-08：纳入 IBKR 现金

作为用户，我希望自己录入 IBKR USD 现金，让现金与股票一起形成总资产，并在明确的利率日期、NAV 和免息门槛下查看利息估算，同时不损坏手机里已有的股票数据。

### US-09：查看今日盈亏

作为用户，我希望在总资产下方直接看到整个股票组合的今日盈亏估算金额和组合涨跌幅，并让它在夜盘等有效时段随行情刷新，以便无需进入其他入口就能判断当前价格变化对股票仓的影响；现金不参与该数值。

### US-10：复制持仓资料

作为用户，我希望在复制前先选择“留在当前页面”或“打开 ChatGPT”，再对前 5、前 10、全部或单只持仓使用同一份低噪音事实资料，以便粘贴到任意应用，或在 ChatGPT 待发送输入框中核对后手动发送；任一路径失败时仍能手工复制/粘贴，同时不改变本地资产数据。

### US-11：从空组合恢复当前资产

作为用户，我希望在完全空的组合中先核对旧 JSON v2 或双券商 JSON v3 预览，再恢复对应 current，以便本地数据丢失后自助取回资产，同时避免误合并、覆盖或半恢复。

### US-12：理解组合结构与今日贡献

作为用户，我希望查看股票集中度、现金占比和今日波动贡献，以便识别主要暴露与驱动来源，并在数据缺失时明确知道结果只是部分口径。

### US-13：查看真实当日持仓估算线

作为用户，我希望在总资产下直接看到真实市场日内价格点对当前持仓的估算影响，并在图上探查时点；数据不足时我希望看到诚实缺失说明，不希望一条虚构的长期收益线。

### US-14：基于完整当前组合持续咨询

作为用户，我希望“组合分析”和“巴菲特框架顾问”是两个清楚、独立的入口：前者点按后直接使用当前持仓、成本、估值、盈亏、现金和行情上下文生成行业/资产角色暴露与六维体检；后者是非冒充的公开价值投资原则模拟，打开即可输入，只有发送时才建立固定的当前组合上下文，并能持续理解最近对话。我希望每个回答都显示使用的 framework lenses 和本机证据，没有一手基本面时明确停在证据不足，数字仍来自 App 本机真值，失败时不影响确定性分析，也不出现目标价、收益保证、预测或直接交易指令。

### US-15：在正确券商记录买卖并联动现金

作为同时使用 IBKR 与 moomoo 的用户，我希望股票仍合并查看、现金也只看一个组合总额；每次买入或卖出只选择股票所在券商，系统就同步更新该券商股数与剩余成本，并从组合现金扣除买入款或加入净卖出款；这样我不需要手工改现金，也不会把 BOXX/SGOV 当成特殊规则。

## 7. 成功与发布判断

### 7.1 首要成功标准

在目标 iPhone 上，用户无需自由创建券商账户；旧 current 可继续使用，启用 v4 后只在交易时选择固定 IBKR/moomoo，并在首页直接识别：

- 组合总仓位；
- 相同标的合并后的结果；
- 页面级行情延迟说明，以及缺价或请求故障；
- 任何未被健康定价的持仓；
- 修改时回填的当前合并数量与均价，以及保存后的替换边界；
- 加仓后的叠加结果与删除前的明确确认。
- 当前账号活动资产可以导出 JSON v2 或 v3；在股票、现金与 v4 book 都为空的登录账号中，可先预览再通过单次 D1 CAS 原子恢复，非空目标、无效文件或失败不会改变任何账号资产。
- 首页可以对前 5、前 10、全部或单只资料分别完成“仅复制”与“复制并打开 ChatGPT”；两个目标的文本与单只组合摘要、占比和排名一致。普通复制不离开 PWA，ChatGPT App 或网页显示待发送 Prompt；失败时可手工回退，动作前后本地数据不变且不自动发送。
- 首页可以在 USD 与人民币之间统一切换金额；数量和收益率不变，人民币模式清楚披露汇率与估算边界。
